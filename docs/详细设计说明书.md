### 1.3 术语与缩写

| 术语 | 含义 |
| --- | --- |
| **主进程（Main）** | Electron 的主进程，负责窗口、原生菜单、文件系统、数据库、导出等系统能力 |
| **预加载（Preload）** | 运行在渲染进程之前、拥有受限 Node 能力的脚本，通过 `contextBridge` 暴露白名单 API |
| **渲染进程（Renderer）** | 承载全部界面与编辑器逻辑的 Chromium 进程 |
| **IPC** | 进程间通信。本项目中渲染进程 → 主进程统一使用 `ipcRenderer.invoke` / `ipcMain.handle`（请求-应答），主进程 → 渲染进程统一使用 `webContents.send`（单向广播） |
| **Live Preview（实时渲染）** | 编辑区内 Markdown 语法即时呈现为排版效果，光标所在行展开源码 |
| **源码模式** | 显示纯 Markdown 源码、不做渲染的编辑模式 |
| **Decorator（装饰器）** | CodeMirror 6 的 `Decoration` 机制，用于在不修改文档内容的前提下改变显示效果 |
| **Widget** | CodeMirror 6 的 `WidgetType`，用于把一段文档区间替换为自定义 DOM |
| **Compartment** | CodeMirror 6 的可动态重配置单元，用于运行期切换扩展组合 |
| **命令（Command）** | 一个可被菜单、工具栏、快捷键触发的具名动作，唯一标识形如 `format.bold` |
| **命令 ID** | 命令的唯一标识字符串，是快捷键绑定、菜单广播与命令实现之间的契约键 |
| **工作区（Workspace）** | 用户通过「打开文件夹」载入的根目录 |
| **资源目录** | 粘贴 / 拖拽图片自动落盘的目录，默认 `assets` |
| **FTS5** | SQLite 的全文检索虚拟表模块，本项目中用于跨文件搜索 |
| **WAL** | SQLite 的 Write-Ahead Logging 日志模式，本项目中用于提升并发读写表现 |
| **零原生模块** | 项目不依赖任何需要本地编译的 native addon，`npm install` 即完成，打包零编译风险 |

### 2.2 进程模型与安全边界

| 进程 | 运行环境 | 拥有的能力 | 禁止事项 |
| --- | --- | --- | --- |
| 主进程 | Node.js 完整能力 | 窗口、原生菜单、对话框、文件系统、数据库、子进程（Pandoc）、系统浏览器、隐藏窗口渲染 | 不承载任何业务界面逻辑 |
| 预加载脚本 | Node + DOM（隔离上下文） | 读取被允许的 Electron 模块（`contextBridge`、`ipcRenderer`、`webUtils`） | 不向页面传递 `ipcRenderer` 本身、不传递函数与原生对象 |
| 渲染进程 | 浏览器环境 | DOM、CSS、CodeMirror 6、markdown-it、KaTeX、Shiki、Mermaid | 不能直接访问文件系统、不能 `require` Node 模块、不能访问 `ipcRenderer` |

**关键安全配置**（`src/main/window.ts` 中 `createMainWindow`）：

| 配置项 | 取值 | 设计意图 |
| --- | --- | --- |
| `contextIsolation` | `true` | 预加载与页面脚本运行在隔离的 JS 上下文，页面无法篡改预加载逻辑 |
| `nodeIntegration` | `false` | 页面拿不到 `require` / `process` |
| `sandbox` | `false` | 本项目预加载脚本使用 `webUtils` 等模块，需关闭渲染器沙箱；安全性由「不暴露 Node 能力 + 严格 CSP + 白名单 IPC」共同保障 |
| `spellcheck` | `true` | 为拼写检查功能预留 |
| `webgl` | `false` | 本软件不需要 WebGL，关闭以降低攻击面与显存占用 |
| `backgroundThrottling` | `false` | 保证后台窗口的定时器与编辑器渲染不被节流 |

```text
renderer/main.ts ──► editor/{editor, markdown, mermaid}
                     core/{store, ui-kit}
                     ui/sidebar 与 ui/overlays

renderer/editor/markdown.ts ──────► shared/path-utils
```

**依赖方向约束**：

1. `shared/` 不得依赖 `main/` 或 `renderer/`（它是两端共享的叶子层）。
2. `main/` 与 `renderer/` 之间不存在直接 import，只能通过 IPC 契约通信。
3. `renderer/editor/` 不得直接调用 `window.hsm.*`（编辑器内核保持纯函数化与可测试），系统能力由 `renderer/main.ts` 通过回调与 Hook 注入。
   - 现存例外：`editor.ts` 与 `live-preview.ts` 通过 `renderer/core/store.ts` 的 `getSetting` 读取设置，这使编辑器内核依赖了应用状态模块。属于可接受的折中，但新增依赖时应优先走参数注入。

## 3 主进程设计

### 3.1 启动流程

```text
main.ts 顶层（app ready 之前）
  ├─ app.setName('花生苗Markdown编辑器')        ← 决定 userData 目录名，必须最早执行
  ├─ win32: app.setAppUserModelId('com.huashengmiao.markdown')  ← 任务栏图标分组
  ├─ linux: appendSwitch('no-sandbox')          ← 关闭 Chromium 沙箱告警刷屏
  ├─ appendSwitch('high-dpi-support','1')       ← 高分屏渲染质量
  ├─ appendSwitch('force-device-scale-factor','1')
  └─ app.requestSingleInstanceLock()
        ├─ 未获得锁 → 记录日志后 app.quit()（单实例约束）
        └─ 获得锁 → 注册 second-instance 事件 → bootstrap()

bootstrap()
  ├─ installGlobalErrorHandlers()     ← uncaughtException / unhandledRejection 落日志
  └─ app.whenReady().then(...)
        ├─ 1. initDatabase()          ← 建表 + PRAGMA；失败降级内存库
        ├─ 2. pruneMissingRecent()    ← 清理已失效的最近文件记录
        ├─ 3. registerIpcHandlers()   ← 注册全部 IPC 通道
        ├─ 4. installApplicationMenu(broadcastCommand)  ← macOS 原生菜单
        └─ 5. createMainWindow(启动文件) ← 从 argv 解析文件路径（文件关联/命令行）

退出路径
  app.on('window-all-closed') 非 darwin → app.quit()
  app.on('before-quit') → unwatchAll() + closeDatabase()（WAL checkpoint 落盘）

macOS 专有
  app.on('activate')      无窗口时重建主窗口
  app.on('open-file')     阻止默认行为，把路径发给已有窗口或新建窗口
```

**命令行文件解析规则**（`extractFileFromArgv`）：从 `argv[1]` 起跳过以 `-` 开头的开关与可执行文件路径，跳过 `app.getAppPath()`（开发模式下 npm 传入的项目目录），第一个「存在且是文件」的参数即作为待打开文件。解析失败静默忽略，不影响启动。

### 3.2 窗口管理

**窗口参数**（`createMainWindow`）：

| 参数 | 取值 | 说明 |
| --- | --- | --- |
| 默认尺寸 | 1280 × 820 | 首次启动尺寸 |
| 最小尺寸 | 760 × 480 | 低于此尺寸界面元素会重叠 |
| `frame` | `isMac()` | macOS 保留系统边框，Windows / Linux 完全无边框 |
| `titleBarStyle` | macOS：`hiddenInset`，其他：`default` | macOS 保留红黄绿交通灯并隐藏标题文字 |
| `thickFrame` | `true` | 无边框窗口仍可从边缘拖拽缩放（仅 Windows 生效） |
| `show` | `false` | 先隐藏，待 `ready-to-show` 后再显示，避免白屏闪烁 |
| `backgroundColor` | `#ffffff` | 首屏底色 |
| `icon` | `resources/icon.png`（存在时） | 开发期窗口图标 |
| `webPreferences.preload` | `dist/preload/preload.js` | 预加载脚本 |

**自绘标题栏方案**：
Windows / Linux 使用 `frame: false`，由渲染进程绘制品牌标识、菜单栏、文件名、未保存标记与最小化 / 最大化 / 关闭按钮；macOS 使用 `hiddenInset` 保留系统交通灯。标题栏的拖拽由 CSS 的 `-webkit-app-region: drag` 区域控制，交互元素使用 `no-drag`。

**窗口状态记忆**：

```text
resize / move 事件 → 600 ms 防抖 → saveWindowState()
  · 若窗口处于最大化或全屏状态则直接返回（不记录尺寸，避免下次启动占满屏幕）
  · 否则写入 window.width / window.height / window.x / window.y
maximize / unmaximize → 写入 window.maximized 并广播 win:maximize-changed
```

启动时 `resolveWindowBounds()` 读取上述值并做三重兜底：尺寸非法或小于最小值时回退默认值；坐标不在任何显示器 `workArea`（允许 50 px 容差）内时改为居中显示——用于处理用户拔掉外接显示器的场景。

> ⚠️ 上述 `window.*` 键**不在** `SETTING_DEFS` 中，因此 `settings` 表把它们按字符串存储，读取时 `Number.isFinite('1280') === false` 会命中回退分支，导致**窗口几何记忆实际未生效**（不影响功能正确性，仅影响体验）。详见[附录 C-1-1](#c-1-1-窗口几何记忆读取失效)。

**关闭拦截流程**（未保存提示）：

```text
用户点击关闭 → win.on('close') 且 allowClose === false
   → e.preventDefault()
   → webContents.send('win:close-request')
        → 渲染进程检查脏标签，弹出 dialog:confirm-unsaved
             ├─ 「保存」   → 保存成功后再继续
             ├─ 「不保存」 → 直接继续
             └─ 「取消」   → 中止关闭流程
   → 渲染进程调用 win.confirmClose() → IPC 'win:confirm-close'
        → 主进程执行 win.hsmConfirmClose()
             → allowClose = true; saveWindowState(win); win.close()
```

**多窗口**：`windows: Set<BrowserWindow>` 维护全部窗口。`getFocusedWindow()` 优先返回聚焦窗口，否则返回第一个存活窗口；`getAllWindows()` 返回全部存活窗口，用于命令广播。`app.newWindow` 通道可再开主窗口（对应命令 `file.newWindow`）。

### 3.3 菜单策略

| 平台 | 策略 | 原因 |
| --- | --- | --- |
| macOS | 构建**完整中文原生菜单**（应用 / 文件 / 编辑 / 格式 / 视图 / 窗口 / 帮助） | macOS 必须提供应用菜单，否则 `⌘Q`、`⌘C`、`⌘V` 等系统级快捷键不可用 |
| Windows / Linux | `Menu.setApplicationMenu(null)`，不显示系统菜单栏 | 界面采用自绘标题栏 + 应用内菜单栏，全部功能快捷键由渲染进程统一处理，便于用户自定义；同时避免出现多余的系统菜单栏 |

macOS 菜单中：

- 使用系统 `role`（`undo` / `redo` / `cut` / `copy` / `paste` / `pasteAndMatchStyle` / `delete` / `selectAll` / `minimize` / `zoom` / `front` / `togglefullscreen` / `toggleDevTools` / `resetZoom` / `zoomIn` / `zoomOut` / `services` / `hide` / `hideOthers` / `unhide` / `quit`）保证输入框内的文本操作符合 macOS 规范；
- 业务菜单项通过 `onCommand(commandId)` 回调 → `broadcastCommand()` → 向所有窗口发送 `app:command`，由渲染进程的 `runCommand(commandId)` 执行，从而**复用同一套命令实现**；
- 「帮助」菜单额外提供「打开日志目录」「打开数据目录」两个直达入口；
- 「关于」对话框（`showAboutDialog`）展示软件简介、版本、作者、微信、MIT 协议以及 Electron / Chromium / Node.js 版本。

| `db:info` | 渲染→主 (invoke) | — | `Array<{ name, label, count }>` | 返回 6 张表的行数统计：`documents`（文档索引）、`document_versions`（版本快照）、`search_content`（搜索索引）、`recent_files`（最近文件）、`export_history`（导出历史）、`images`（图片记录） |

#### 3.4.16 兜底与主 → 渲染通道

| 通道名 | 方向 | 参数 | 说明 |
| --- | --- | --- | --- |
| `__unknown__` | 渲染→主 (`ipcMain.on`) | — | 兜底监听：任何未注册通道的同步调用返回 `null`，避免渲染进程无限等待 |

| `fs:file-changed` | 主→渲染 (send) | `string`（文件路径） | 被监视文件发生 `change` / `rename`（外部修改） |
| `win:maximize-changed` | 主→渲染 (send) | `boolean` | 窗口最大化状态变化（用于更新「最大化 / 还原」按钮图标） |

| `win:close-request` | 主→渲染 (send) | — | 请求渲染进程确认关闭（未保存检查入口） |
| `search:progress` | 主→渲染 (send) | `{ done: number, total: number }` | 工作区索引重建进度（每 20 个文件上报一次） |

### 3.5 IPC 约定与错误处理

| 约定 | 实现 |
| --- | --- |
| 路径参数校验 | 所有接收路径的通道统一经 `assertPath()`：必须是非空字符串，并 `path.resolve()` 规范化，避免越权与相对路径歧义 |
| 异常隔离 | 可能抛异常的通道用 `fail(e)` 包装为 `{ ok:false, error: string }`，同时 `logError('IPC 调用失败', e)` 落日志，防止渲染进程收到未捕获异常 |
| 返回值可空性 | 对话框类通道取消时返回 `null`；查询类通道失败时返回空数组或 `undefined` 语义的安全值（`recent:list` → 清理后列表；`theme:custom-list` → `[]`） |
| 幂等性 | `fs:watch`、`recent:add`（累加语义除外）、`history:snapshot`（同内容跳过）、`settings:set`（UPSERT）均设计为可重复调用 |
| 副作用顺序 | `fs:open-file-by-path` 内部固定顺序：读文件 → 写最近文件 → 建索引 → 注册监视；`fs:write-file` 成功后才更新索引 |
| 类型安全 | 全部通道的参数与返回值类型定义在 `src/shared/types.ts` 的 `HsmApi` 接口中，预加载脚本按该契约实现，两端共享同一份类型 |

## 4 数据存储设计

### 4.1 初始化与连接配置

**存储选型**：Node.js 内置的 `node:sqlite`（`DatabaseSync` / `StatementSync`）。

选择它的核心理由：

1. **零原生模块**——不需要 `better-sqlite3` 之类的 native addon，用户与开发者都无需 Python / Rust / 编译器，`npm install` 即完成，打包无编译风险；
2. **自带 FTS5**——Node.js 发行版内置的 SQLite 已编译 FTS5 模块，可直接提供全文检索；
3. **同步 API**——主进程中的读写为同步调用，逻辑简单、无回调地狱，且数据量可控（单机个人笔记场景）。

**初始化流程**（`initDatabase`）：

```text
1. 解析路径：<userData>/huashengmiao.db（目录不存在则递归创建）
2. new DatabaseSync(databasePath)
3. 执行 PRAGMA：
     journal_mode = WAL          并发读写更友好，崩溃恢复更安全
     synchronous  = NORMAL       兼顾安全与写入速度
     foreign_keys = ON           启用外键约束
     temp_store   = MEMORY       临时表驻内存，加速排序与分组
4. 按依赖顺序执行 SCHEMA_STATEMENTS（建表 + 建索引）
5. 单独 try/catch 创建 FTS5 虚拟表 search_index
     —— 若运行环境的 SQLite 未编译 FTS5，仅记录错误并降级为逐文件 LIKE 搜索，不中断启动
6. 失败兜底：整体异常时改用 new DatabaseSync(':memory:') 建内存库并建表，
   保证「数据库不可用也不影响编辑」；内存库再失败则 database = null，
   所有访问函数返回安全空值
```

**访问封装**：`run` / `get` / `all` / `exec` 四个函数统一走 `getDb()` 单例，并使用 `stmtCache: Map<string, StatementSync>` 缓存预编译语句，避免重复解析 SQL。所有参数通过占位符绑定，杜绝字符串拼接 SQL。

**关闭**：`closeDatabase()` 先执行 `PRAGMA wal_checkpoint(TRUNCATE)` 把 WAL 内容落盘，再 `close()`，并清空语句缓存；由 `app.on('before-quit')` 调用。

```sql
    scope        VARCHAR(32) DEFAULT 'global',
    updated_at   DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- ============================================================
-- 7. 最近文件表
-- ============================================================
CREATE TABLE IF NOT EXISTS recent_files (

    status      VARCHAR(16),
    error_msg   TEXT,

CREATE TABLE IF NOT EXISTS sync_log (
```

| `tokenize` | `unicode61` | 分词器，对以空格分词的英文 / 数字文本表现良好 |

**维护策略**：索引写入采用「先 `DELETE` 再 `INSERT`」保证与原文表一致；FTS5 不可用时静默跳过并记录日志。

### 4.4 数据关系

```text
documents (file_path UNIQUE)
   │
   ├── document_versions.doc_path ────┐（当前实现以 doc_path 关联，
   │                                   │  不使用外键约束）
   ├── images.doc_path ───────────────┤
   ├── search_content.doc_path (PK) ──┤

sync_log / plugins             独立表，功能预留
```

### 4.5 降级策略

| 故障 | 降级行为 | 用户可感知的影响 |
| --- | --- | --- |
| 用户数据目录不可写 | 改用内存数据库 `:memory:` | 当次会话可用；重启后设置、最近文件、快照、索引丢失 |
| 内存库创建也失败 | `database = null`，所有数据访问返回安全空值 | 编辑与导出仍可用；搜索、历史、最近文件不可用 |
| SQLite 未编译 FTS5 | 跳过 `search_index` 创建，仅用 `search_content` 的 LIKE 通道 | 搜索仍可用，超大工作区下英文检索略慢 |
| 单条 SQL 执行失败 | `logError` 记录并返回 `null` / `undefined` / `[]` | 该次操作静默失败，不影响其它功能 |
| 数据库文件损坏 | 启动时 `initDatabase` 抛异常 → 降级内存库 | 建议用户备份并删除 `huashengmiao.db` 后重启 |

### 4.6 与需求规格说明书的差异

| 项目 | 需求规格说明书 §8 | 实现 | 说明 |
| --- | --- | --- | --- |
| `document_versions` 关联方式 | 通过 `document_id` 外键关联 `documents` 并 `ON DELETE CASCADE` | 增加 `doc_path` 字段并按路径关联，写入时 `document_id` 固定为 `0`，未声明外键 | 快照按路径直接分组，避免「文档未登记进 `documents` 表」导致外键失败 |
| 搜索索引表 | 一张 FTS5 表 `search_index(document_id, title, content)` | 拆为 `search_content`（原文表，PK `doc_path`）+ `search_index`（FTS5，`doc_path UNINDEXED`） | 中文连写场景下 `unicode61` 分词命中率低，用原文表 + LIKE 兜底；详见 §11.5 |
| 会话状态 | 未列出 | 新增 `session_state` 表 | 支撑「启动时恢复上次会话」需求 |
| `plugins` / `sync_log` | 已列出（预留） | 已建表（预留） | 一致 |

## 5 渲染引擎设计

渲染引擎实现位于 `src/renderer/editor/markdown.ts`，职责是把 Markdown 源码渲染为 HTML 片段，供「导出」与「表格 / 代码块的块级渲染」使用；编辑区内的行内实时渲染由 §6 的装饰器负责，两者共享同一套类名约定与安全策略。

### 5.1 markdown-it 实例配置

```ts
new MarkdownIt({
  html: false,          // 【安全】不解析原始 HTML，用户文档中的 <script> 等一律按纯文本输出
  xhtmlOut: false,      // 输出 HTML5 风格的自闭合标签
  breaks: false,        // 单个换行不产生 <br>，与 Typora 行为一致
  langPrefix: 'language-',  // 代码块 class 前缀，与 Shiki 约定一致
  linkify: true,        // 自动识别裸链接（http://... 直接变可点击链接）
  typographer: false,   // 关闭智能标点替换，保持源码原样
  highlight(code, lang) { /* 见 §5.5 */ },
})
```

| 选项 | 取值 | 设计理由 |
| --- | --- | --- |
| `html` | `false` | **核心安全开关**。实时渲染与导出都不允许文档内嵌 HTML 被执行，CSP 的 `script-src 'self'` 与之形成双保险 |
| `breaks` | `false` | Typora 中单个回车不换行，必须空行才分段；与用户习惯一致 |
| `linkify` | `true` | 满足「自动链接」语法要求，无需用户手写 `[]()` |

### 5.2 插件清单与注册顺序

`createMarkdownIt()` 中按以下顺序注册（顺序不可随意调整）：

| 序号 | 插件 | 注册参数 | 支撑的语法 |
| --- | --- | --- | --- |
| 1 | `markdown-it-emoji`（`full` 导出） | — | Emoji 短代码 `:smile:` |
| 2 | `markdown-it-footnote` | — | 脚注 `[^1]` 与文末脚注区（`.footnotes`） |
| 3 | `markdown-it-task-lists` | `{ enabled: true, label: true, labelAfter: true }` | 任务列表 `- [ ]` / `- [x]`，渲染为可点击复选框（`li.task-list-item`） |
| 4 | `markdown-it-mark` | — | 高亮 `==text==` → `<mark>` |
| 5 | `markdown-it-sub` | — | 下标 `H~2~O` → `<sub>` |
| 6 | `markdown-it-sup` | — | 上标 `x^2^` → `<sup>` |
| 7 | `markdown-it-deflist` | — | 定义列表 → `<dl>` / `<dt>` / `<dd>` |

> `markdown-it-task-lists` 的许可证为 **ISC**（其余 markdown-it 插件均为 MIT），许可证类型与合规结论见 [`THIRD-PARTY-LICENSES.md`](../THIRD-PARTY-LICENSES.md)。

### 5.3 自定义插件

#### 5.3.1 数学公式插件

在 `inline.ruler` 的 `escape` 规则之前插入 `math_inline`，在 `block.ruler` 的 `fence` 规则之前插入 `math_block`（`alt: ['paragraph','reference','blockquote','list']`）。

**行内规则** `mathInlineRule` 的判定条件：

| 条件 | 说明 |
| --- | --- |
| 起始字符必须是 `$` 且后面紧跟的字符不是 `$` | 排除 `$$`（交给块级规则） |
| 内容不跨行 | 遇到 `\n` 直接返回 `false` |
| 支持 `\$` 转义 | 扫描时遇到 `\` 跳过两个字符 |
| 内容首尾不为空白 | 排除 `$ 100 $` 这类写法 |
| 内容不能全为数字 / 逗号 / 点 / 空格 | 排除 `$5`、`$1,000` 等金额写法 |

命中后压入 `math_inline` token，渲染为 `<span class="hsm-math-inline">…</span>`。

**块级规则** `mathBlockRule` 的判定条件：

| 条件 | 说明 |
| --- | --- |
| 行首（含缩进）必须是 `$$` | 起始标记 |
| 缩进超过 3 个空格不算块级公式 | 与列表缩进语义区分 |
| 支持单行形式 `$$ E=mc^2 $$` | 同行内匹配到第二个 `$$` 即闭合 |
| 支持多行形式 | 逐行查找结束标记，允许结束行内出现 `$$` |
| token 带 `map = [起行, 止行+1]` | 供编辑器与导出的位置换算使用 |

渲染为 `<div class="hsm-math-block">…</div>`。

#### 5.3.2 容器插件

块级规则 `containerRule` 匹配 `::: 类型 标题`，向下查找配对的独立 `:::` 结束行，使用 `state.md.block.tokenize()` 递归解析内部内容，压入 `container_open` / `container_close` token。

| 类型标记 | 中文默认标题 | CSS 类名 |
| --- | --- | --- |
| `warning` / `warn` | 警告 | `hsm-container warning` |
| `tip` | 提示 | `hsm-container tip` |
| `info` | 说明 | `hsm-container info` |
| `note` | 笔记 | `hsm-container note` |
| `danger` / `error` | 危险 / 错误 | `hsm-container danger` |
| `success` | 成功 | `hsm-container success` |
| （未指定类型） | 笔记 | `hsm-container note` |

输出结构：`<div class="hsm-container {类型}"><div class="hsm-container-title">{标题}</div> …内部内容… </div>`。
标题经 `escapeHtml` 转义；`state.parentType` 临时置为 `container` 以保证内部块级解析正确。

### 5.4 KaTeX 接入

```ts
katex.renderToString(tex, {
  displayMode: display,          // true = 块级
  throwOnError,                  // 默认 false：出错时渲染为红色错误文本而非抛异常
  errorColor: '#d1242f',
  strict: false,                 // 宽松模式，容忍部分非标准写法
  trust: false,                  // 【安全】禁止 \htmlClass、\href 等可注入的能力
  macros: { '\\RR': '\\mathbb{R}', '\\NN': '\\mathbb{N}', '\\ZZ': '\\mathbb{Z}' },
})
```

| 设计点 | 说明 |
| --- | --- |
| 容错 | `throwOnError: false` + 外层 `try/catch` 双保险；失败输出 `<span class="hsm-math-error" title="错误原因">原始公式</span>`，样式为红字浅红底 |
| 安全 | `trust: false` 禁止 KaTeX 的可信命令（`\href`、`\htmlId` 等），防止公式中夹带链接或注入 |
| 编号 | 块级公式容器 `.hsm-math-block` 提供 `.hsm-math-number` 定位样式，供编号显示 |
| 导出字体内联 | 导出 HTML 时把 KaTeX 样式表中的 `url(fonts/*.woff2)` 替换为 base64 data URL（详见 §8.2） |

### 5.5 Shiki 接入

```ts
import hljs from 'Shiki/lib/common';   // 只引入常用语言集合，控制包体
```

`highlight(code, lang)` 回调逻辑：

```text
1. 归一化语言标识：取 lang 的第一个词并转小写
2. 若语言是 mermaid / mmd：返回 Mermaid 占位容器
     <div class="hsm-mermaid" data-mermaid="{encodeURIComponent(code)}"></div>
     由渲染进程的 mermaid.ts 异步填充 SVG（详见 §5.6）
3. 若语言存在且 hljs.getLanguage(language) 命中：
     hljs.highlight(code, { language, ignoreIllegals: true }).value
4. 若语言标识存在但 Shiki 不支持：hljs.highlightAuto(code) 自动识别
5. 无语言标识或识别失败：escapeHtml(code) 纯文本
6. 输出：<pre data-lang="{lang}"><code class="hljs language-{lang}">…</code></pre>
     · data-lang 供 CSS 在代码块右上角展示语言名（pre[data-lang]::before）
     · 内容已由 Shiki 转义或 escapeHtml 处理，不二次转义
```

编辑器内的代码块 Widget 复用同一个 `renderCodeBlock(code, lang)` 函数，保证「编辑区所见」与「导出所得」高亮一致。

### 5.6 Mermaid 接入与安全

Mermaid 采用**按需加载 + 独立打包 + 三级缓存**方案，避免 2 MB 级依赖拖慢首屏。

```text
打包期（scripts/build.mjs）
  src/renderer/editor/mermaid-entry.ts → dist/renderer/mermaid.js（IIFE，强制 minify）

运行期（src/renderer/editor/mermaid.ts）
  loadMermaid()
    ├─ 已加载（window.__HSM_MERMAID__ 存在）→ 直接返回
    ├─ 加载中（loadingPromise 存在）→ 复用同一个 Promise，保证并发只注入一次
    └─ 否则创建 <script src="./mermaid.js" async>，
         8 秒超时视为失败，onload 后读取 window.__HSM_MERMAID__

  renderMermaid(source)
    ├─ 命中 renderCache（源码 → SVG HTML）→ 同步返回
    ├─ 命中 errorCache（源码 → 错误 HTML）→ 同步返回（避免反复重试）
    ├─ 命中 pending（源码 → 进行中的 Promise）→ 复用，同图表只渲染一次
    └─ 否则 mermaid.render('hsm-mermaid-' + 随机串, code)
         · 成功 → <div class="hsm-mermaid">{svg}</div> 写入 renderCache
         · 失败 → 输出结构化错误卡片（标题「图表语法有误」+ 原始源码 + 首行错误信息）
  putCache()：缓存上限 MAX_CACHE = 80，超限先淘汰最早条目，防止长文档累积 SVG 撑爆内存
  clearMermaidCache()：切换文档主题 / 代码主题 / 系统明暗时清空，使图表按新配色重绘
  paintMermaid(host, source)：替换 Widget 的 DOM 时先同步填缓存，未命中则显示「正在渲染图表…」
                            并在异步完成后校验 host.isConnected 再写入（防止 CodeMirror 已回收节点）
```

**安全配置**（`mermaid-entry.ts`）：

```ts
mermaid.initialize({
  startOnLoad: false,          // 由本软件控制渲染时机，不让 mermaid 自行扫描 DOM
  securityLevel: 'strict',     // 【安全】严格模式：禁用图表内的脚本与外部资源引用
  theme: 'default',
  fontFamily: '-apple-system, "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif',
  flowchart: { htmlLabels: true, useMaxWidth: true },
  sequence:  { useMaxWidth: true },
  gantt:     { useMaxWidth: true },
  er:        { useMaxWidth: true },
  themeVariables: {
    primaryColor: '#e8f8f1', primaryBorderColor: '#22a06b', primaryTextColor: '#1f2328',
    lineColor: '#8b949e', fontSize: '14px',
  },
});
```

`securityLevel: 'strict'` 使 Mermaid 内部对生成的标签文本做 HTML 消毒（其依赖链中的 `dompurify` 与 `@braintree/sanitize-url` 负责具体过滤），配合页面 CSP 的 `script-src 'self'`，共同保证「恶意图表语法无法注入脚本」。

### 5.7 图片路径解析

图片渲染接管 `md.renderer.rules['image']`，把 Markdown 中书写的地址解析为可直接显示的地址：

```ts
resolveResourceUrl(rawSrc, docPath)   // src/shared/path-utils.ts
  1. http: / data: / blob:  → 原样返回
  2. file:                  → 原样返回
  3. 拆分锚点与查询串（# / ?）后单独处理
  4. 绝对路径（POSIX 或 Windows 盘符）→ toFileUrl()
  5. 相对路径 → 以文档所在目录为基准 resolve() 后 toFileUrl()
  6. 无文档路径（未保存的新文档）→ 原样返回
```

`toFileUrl()` 处理了 Windows 盘符（`C:/a` → `/C:/a`）、路径分段 `encodeURIComponent` 以及 `/ : @ + $ , ; = ! * ' ( )` 等路径合法字符的反编码，避免空格与 `#` `?` 导致图片加载失败。

输出的 `<img>` 结构：

```html
<img src="{解析后地址}" alt="{alt}" data-raw-src="{Markdown 原地址}"
     title="{可选}" style="width:{n}px" data-align="{left|center|right}" loading="lazy">
```

其中 `width` 与 `align` 从图片 `title` 中按 `width=300` / `align=center` 语法解析（`parseImageParams`），对齐样式由 `BASE_DOC_CSS` 的 `img[data-align="..."]` 规则实现。

### 5.8 标题锚点与目录

**锚点生成** `slugify(text, used)`：

| 步骤 | 处理 |
| --- | --- |
| 1 | `trim()` + 转小写 |
| 2 | 去掉行内 Markdown 标记（`* _ ` ~ [ ]`） |
| 3 | 空白与全角空格转 `-` |
| 4 | 移除非字母、非数字、非 `- _ .` 的字符（使用 Unicode 属性 `\p{L}` / `\p{N}`，**中文字符被保留**） |
| 5 | 折叠连续 `-`，去掉首尾 `-`；结果为空时回退 `heading` |
| 6 | 传入 `used` 集合时做去重：`base`、`base-1`、`base-2`… |

`heading_open` 渲染规则在 `renderDocument` 每次调用时重置去重集合（通过规则函数上的 `__reset` 标记），保证同一文档内锚点唯一、跨文档渲染互不污染。

**目录生成** `buildTocHtml(headings)` 输出：

```html
<div class="hsm-toc">
  <div class="hsm-toc-title">目录</div>
  <ul>
    <li class="hsm-toc-level-2"><a href="#锚点">标题文本</a></li>
    …
  </ul>
</div>
```

`[TOC]` 占位符的替换分两条路径：

| 场景 | 处理方式 |
| --- | --- |
| 导出 / 整篇渲染（`renderDocument`） | 渲染完成后用正则把 `<p>[TOC]</p>` 替换为目录 HTML |
| 编辑器实时预览（`live-preview.ts`） | 用 `/^\s*\[TOC\]\s*$/gim` 定位 `[TOC]` 本身，替换为 `TocWidget`；光标在其上时保持源码可见 |

**标题提取** `extractHeadings(src)` 独立于 markdown-it 实现（正行扫描），原因是大纲面板与 `[TOC]` 需要在**任意时刻**（包括文档尚未完整渲染时）快速获取标题列表。扫描时会跳过：YAML Front Matter 区、围栏代码块、块级公式区；支持 ATX（`#`）与 Setext（`===` / `---`）两种形式；标题文本经 `stripInline()` 去掉行内标记后作为纯文本。

### 5.9 文档统计

`computeStats(text)` 的统计口径：

| 指标 | 口径 |
| --- | --- |
| 统计前处理 | 去掉围栏代码块与行内代码内容（避免代码影响字数） |
| `cjkChars` | 中日韩字符数（含平假名、片假名、CJK 扩展 A、兼容汉字区） |
| `words` | 剔除 CJK 后的 `[A-Za-z0-9_'’-]+` 词数 |
| `chars` | 去掉全部空白字符后的字符数 |
| `charsWithSpace` | 含空白的字符数 |
| `lines` | 按 `\r\n` / `\r` / `\n` 切分的行数 |
| `paragraphs` | 以空行分隔的非空段落数 |
| `readingMinutes` | `max(是否有内容 ? 1 : 0, ceil(CJK/300 + 西文词/200))`，即中文 300 字/分钟、英文 200 词/分钟 |

```text
                    └──────────────────────────────┘
```

**核心契约**：**装饰只改变「显示」，绝不修改文档内容**。文档文本始终是用户输入的原始 Markdown，因此保存、撤销重做、搜索、导出都以源码为唯一事实来源；这与「所见即所得」类编辑器中把渲染结果写回文档的做法有本质区别，也是本方案稳定性的基础。

### 6.2 装饰器类型与用途

| CodeMirror API | 本项目的用途 | 典型场景 |
| --- | --- | --- |
| `Decoration.replace({})` | 隐藏语法标记，使其不占据显示空间 | 隐藏 `**`、`#`、`>`、`[TOC]`、两侧 `$` |
| `Decoration.replace({ widget, block: true })` | 把整段区间替换为自定义 DOM（块级） | 代码块、表格、图片、Mermaid、块级公式、分割线、Front Matter |
| `Decoration.replace({ widget })` | 行内替换为自定义 DOM | 列表符号（`BulletWidget`）、任务复选框（`TaskCheckboxWidget`）、目录（`TocWidget`） |
| `Decoration.mark({ class })` | 给内容套样式类，内容仍可编辑 | `hsm-strong`、`hsm-em`、`hsm-del`、`hsm-code`、`hsm-link`、`hsm-mark`、`hsm-math-inline` |
| `Decoration.line({ class })` | 给整行套样式类（不改变内容） | `hsm-line-h1`~`hsm-line-h6`、`hsm-line-quote`、`hsm-line-code`、`hsm-line-table`、`hsm-line-task`、`hsm-line-math`、`hsm-active-line` |
| `Decoration.set(ranges, true)` | 汇总为一个有序装饰集合（第二参数 `true` 表示已排序） | 所有场景 |

**行装饰去重**：`lineDecorated: Set<number>` 保证同一行只添加一次行装饰。例如列表项既命中 `TaskMarker`（需要 `hsm-line-task`）又可能命中其它规则时，不会产生冲突的行装饰。

### 6.3 语法树遍历

```ts
const tree = syntaxTree(state);      // @codemirror/language + @codemirror/lang-markdown(@lezer/markdown)
tree.iterate({
  enter(ref) {
    const node = ref.node;
    switch (node.name) { /* 见下表 */ }
    return skipChildren ? false : undefined;   // false = 不再深入该节点子树
  },
});
```

遍历到的节点类型与处理策略：

| 节点名 | 生成的装饰 | 说明 |
| --- | --- | --- |
| `ATXHeading1` … `ATXHeading6` | 行装饰 `hsm-line-h{n}` + 隐藏 `HeaderMark`（连同其后的一个空格） | 光标在该行时不隐藏 |
| `SetextHeading1` / `SetextHeading2` | 行装饰 `hsm-line-h1/h2` + 整行隐藏下划线行（`===` / `---`） | 光标不在该标题所在行时隐藏 |
| `FencedCode` / `CodeBlock` | 选区相交 → 仅加 `hsm-line-code`（显示源码）；否则整个代码块替换为 `CodeBlockWidget` 或 `MermaidWidget` | 语言为 `mermaid` / `mmd` 时走 Mermaid 分支；设 `skipChildren` 跳过内部节点 |
| `Blockquote` | 多行 `hsm-line-quote` + 逐行隐藏行首 `>` 标记（`/^(\s*)(>+\s?)/`） | 光标所在行保留 `>` |
| `BulletList` / `OrderedList` | 用 `node.cursor()` 遍历所有 `ListMark`，替换为 `BulletWidget`（含标记后的一个空格） | 无序列表统一显示 `•`，有序列表保留原始编号 |
| `TaskMarker` | 替换为 `TaskCheckboxWidget` + 行装饰 `hsm-line-task` | 复选框点击直接改写源码中的 `[ ]` / `[x]` |
| `HorizontalRule` | 整行替换为 `HorizontalRuleWidget`（`block: true`） | 排除 Front Matter 首行的 `---`；光标所在行不替换 |
| `Table` | 选区相交 → 仅加 `hsm-line-table`；否则整块替换为 `TableWidget` | HTML 由 `renderTable(md, source)` 生成；设 `skipChildren` |
| `Image` | 替换为 `ImageWidget`（含路径解析、宽度、加载失败提示） | 选区相交时不替换 |
| `StrongEmphasis` | `Decoration.mark('hsm-strong')` + 隐藏内部 `EmphasisMark` | 光标不在区间内时隐藏 `**` |
| `Emphasis` | `Decoration.mark('hsm-em')` + 隐藏 `EmphasisMark` | 同上 |
| `Strikethrough` | `Decoration.mark('hsm-del')` + 隐藏 `EmphasisMark` | `~~` |
| `InlineCode` | `Decoration.mark('hsm-code')` + 隐藏 `CodeMark` | 反引号 |
| `Link` | `Decoration.mark('hsm-link')` + 隐藏 `URL` / `LinkTitle` 与 `(` `)` `](`；**保留 `[` 与 `]`** | 链接文字保持可见可编辑 |
| `Autolink` | `Decoration.mark('hsm-link')` | 裸链接 |
| `Highlight` | `Decoration.mark('hsm-mark')` | `==text==` |

> 表格与代码块的 Widget 需要接收点击事件（浮动工具条、复选框、Mermaid 内部交互），因此其 `ignoreEvent()` 返回 `false`；`ViewPlugin` 同时提供 `eventHandlers.mousedown`，对 `.hsm-widget` 内的目标返回 `false` 让 Widget 自行处理。

### 6.4 光标行与选区展开策略

这是「想改哪里就看哪里」的实现关键，由两个判定函数构成：

```ts
/** 判断区间是否与当前选区相交（含零长度光标落在边界的情况） */
overlapsSelection(state, from, to)
  for each range r in state.selection.ranges:
      f = min(r.from, r.to); t = max(r.from, r.to)
      if (f <= to && t >= from) return true     // 边界相接也算相交

/** 判断某一行是否包含光标/选区端点 */
lineHasCursor(state, lineFrom, lineTo)
  for each range r:
      if (r.from ∈ [lineFrom, lineTo]) return true
      if (r.to   ∈ [lineFrom, lineTo]) return true
```

| 语法元素 | 展开（显示源码）的条件 |
| --- | --- |
| 标题 `#` 标记 | 光标在该标题所在行 |
| Setext 下划线行 | 光标在该标题所在行 |
| 引用 `>` 标记 | 光标在某一行 |
| 列表标记 / 任务复选框 | 光标在该行 |
| 分割线 | 光标在该行 |
| 加粗 / 斜体 / 删除线 / 行内代码 / 链接 / 高亮 | **选区与节点区间相交**（粒度是区间而非行） |
| 行内公式 `$` | 选区与公式区间相交（隐藏两侧 `$`） |
| 代码块 / 表格 | 选区与整个块区间相交（整块显示源码，便于编辑） |
| Mermaid / 图片 / 块级公式 | 选区相交时不替换 |
| Front Matter | 光标落在起止标记之间时不折叠 |
| `[TOC]` | 光标在 `[TOC]` 上时不替换 |

设计要点：**行级元素按「行」展开，行内元素按「区间」展开**。前者符合「光标在哪一行，那一行就显示源码」的直觉；后者保证「选中加粗文字」时只展开这一段，而不是整行。

### 6.6 公式的正则预扫描

由于 `@lezer/markdown` 不认识 `$$...$$` 与 `$...$`，公式在装饰阶段**不依赖语法树**，而是用两个专用扫描函数实现：

**`scanMathBlocks(state, frontMatterEndLine)`**：

| 规则 | 说明 |
| --- | --- |
| 跳过 Front Matter 区 | 行号 ≤ Front Matter 结束行的直接 continue |
| 跳过围栏代码块 | 识别 ` ``` ` / `~~~` 起止，块内不解析 |
| 起始 `$$` 缩进不超过 3 个空格 | 否则视为普通段落内容 |
| 支持单行 `$$x=1$$` | 起始行内即可闭合 |
| 支持多行 | 记录 `openFrom` / `openContentStart`，在后续行查找结束 `$$` |
| 产出 | `{ from, to, tex }` 数组，供后续生成 `MathBlockWidget` |

**`scanInlineMath(state, mathBlocks, frontMatterEndLine)`**：

| 规则 | 说明 |
| --- | --- |
| 跳过 Front Matter 与围栏代码块 | 同上 |
| 跳过块级公式覆盖区 | 通过 `mathBlocks.some(...)` 判断（带 ±2 字符容差） |
| 正则 `/(?<!\\)\$([^$\n]+?)(?<!\\)\$/g` | 用后行否定断言排除被转义的 `\$`；内容不跨行 |
| 排除纯数字内容 | `/^[\d,.\s]+$/` 视为金额而非公式 |
| 排除行内代码中的 `$` | 统计 `$` 之前出现的反引号数量，奇数说明处于行内代码中 |
| 产出 | `{ from, to, tex, innerFrom, innerTo }`，隐藏两侧 `$` 时使用 inner 边界做 mark |

### 6.7 重算触发与增量

`livePreview()` 返回一个 `ViewPlugin`，其 `update(update)` 逻辑：

```ts
const contentChanged   = update.docChanged;
const selectionChanged = update.selectionSet;
const viewportChanged  = update.viewportChanged || update.geometryChanged;

if (!contentChanged && !selectionChanged && !viewportChanged) return;   // 否则完全跳过

const built = buildDecorations(update.view.state, deps, {
  computeHeadings: contentChanged,     // 仅内容变化时重新提取标题
  previousHeadings: this.headings,     // 选区变化时复用上一次结果
});
this.decorations = built.decorations;

if (contentChanged) {
  this.headings = built.headings;
  const sig = signatureOf(built.headings);         // "level:line:text|…"
  if (sig !== this.headingSignature) {             // 标题确实变化才通知
    this.headingSignature = sig;
    onHeadings?.(built.headings);                  // 刷新大纲面板
  }
}
```

**三项优化**：

1. **按需重算**——文档、选区、视口三者都未变化时直接返回，避免无意义开销；
2. **标题提取复用**——`extractHeadings` 是全文扫描，代价较高，因此只在内容变化时执行；选区变化（例如按方向键移动光标）复用上一次的标题列表；
3. **标题签名去重**——用拼接签名比较标题列表，只有真实变化才回调 `onHeadings`，避免大纲面板频繁重绘。

### 6.8 模式切换机制

实时渲染与源码模式通过 `Compartment` + 重建 `EditorState` 两种手段配合实现：

```ts
// editor.ts
export const previewCompartment = new Compartment();      // 实时渲染开关
export const lineNumbersCompartment = new Compartment();  // 行号开关
export const wrapCompartment = new Compartment();         // 自动换行开关

// 构建扩展时
sourceMode = !getSetting<boolean>('editor.livePreview', true);
previewCompartment.of(livePreviewEnabled ? livePreview(deps.preview, deps.onHeadings) : []),
```

切换流程（`main.ts` 的 `toggleSourceMode` → `rebuildEditorState`）：

```text
1. 记录当前文档内容与选区
2. 写入设置 editor.livePreview = !sourceMode（同时持久化到数据库）
3. newState(content) 重新构造 EditorState（读取新设置决定是否装载实时渲染扩展）
4. view.setState(rebuilt)
5. 把光标位置恢复到 min(原位置, 新文档长度)
6. #app 上切换 is-source-mode 类（用于样式区分）
7. 刷新状态栏
8. Toast 提示「已切换到源码模式 / 已切换到实时预览」
```

源码模式下的 `sourceModeExtension` 仅提供一个字体主题（`EditorView.theme`），语法着色交由 `syntaxHighlighting(defaultHighlightStyle)` 承担——即源码模式保留基础语法着色，不做排版渲染。

### 6.10 已知限制

| 限制 | 说明 | 影响 |
| --- | --- | --- |
| 重算粒度为全文 | `buildDecorations` 遍历整棵语法树并 `doc.toString()`；`scanMathBlocks` / `scanInlineMath` 逐行扫描全文 | 百 KB 级文档下每次按键的重算成本随文档增长；见 §11.2 |

## 7 文件与图片处理设计

### 7.1 编码与换行识别

**读取**（`readTextFile`）：

```text
1. 读入 Buffer
2. BOM 检测：若前三字节为 EF BB BF，剥离 BOM，编码标记为 'UTF-8 BOM'
3. 严格 UTF-8 解码：new TextDecoder('utf-8', { fatal: true })
      ├─ 成功 → 编码 'UTF-8'
      └─ 失败 → new TextDecoder('gbk') 解码，编码 'GBK'（并记录日志）
             └─ 再失败 → new TextDecoder('utf-8', { fatal: false }) 有损解码，编码 'UTF-8（有损）'
4. 换行识别：分别统计 \r\n 与「非 \r 的 \n」数量，CRLF 多则判定为 'CRLF'，否则 'LF'
5. 返回 OpenedFile { path, content, encoding, eol, size, mtime }
```

**写入**（`writeTextFile`）：

```text
1. 递归创建父目录
2. 读取旧文件，统计其换行风格
3. 若旧文件以 CRLF 为主 → 把新内容中的 \r?\n 统一替换为 \r\n（保持原风格，避免整文件差异）
4. writeFile(..., 'utf8')
5. 返回 { ok, mtime }，失败返回 { ok:false, mtime:0, error }
```

**错误翻译**（`describeFsError`）：把 Node 的 `errno` 码翻译为中文可读提示——

| 错误码 | 中文提示 |
| --- | --- |
| `EACCES` / `EPERM` | 没有权限访问该位置，请检查文件是否被占用或换个目录 |
| `ENOENT` | 文件或目录不存在 |
| `EEXIST` | 同名文件或文件夹已存在 |
| `ENOSPC` | 磁盘空间不足 |
| `EBUSY` | 文件被其它程序占用，请关闭后重试 |
| `EISDIR` | 目标是一个目录 |
| `ENOTDIR` | 目标不是目录 |
| `EROFS` | 目标位于只读文件系统 |
| 其它 | 原始 `err.message` 或「未知错误」 |

### 7.2 目录树构建

```text
readTree(root, depth = 3) → buildNode(root, depth, isRoot)

buildNode(target, depth, isRoot)
  1. stat 失败 → 视为文件节点（容错）
  2. 非目录 → 文件节点 { name, path, type:'file', size, mtime, isMarkdown }
  3. depth <= 0 → 仅返回文件夹节点，不展开子项（惰性展开的基础）
  4. readdir(withFileTypes)；读取失败仅记录日志并返回空 children
  5. 过滤：
       目录：忽略 IGNORED_DIRS = { node_modules, .git, .svn, .hg, .idea, .vscode,
                                    $RECYCLE.BIN, System Volume Information }
             以及所有以 '.' 开头的目录
       文件：忽略 IGNORED_FILES = { .DS_Store, Thumbs.db, desktop.ini }
  6. 排序：
       目录：按 zh-CN 区域设置升序
       文件：Markdown 文件优先，其次按 zh-CN 区域设置升序
       最终 children = 目录节点 + 文件节点
  7. 单层节点数上限 MAX_CHILDREN = 2000（防止超大目录拖死界面）
```

**Markdown 扩展名集合**（`MARKDOWN_EXTS`）：`.md` `.markdown` `.mdx` `.txt` `.mdown` `.mkd`。

### 7.3 增删改移

| 操作 | 函数 | 关键行为 |
| --- | --- | --- |
| 新建文件 | `createFile(dir, name)` | 名称为空拒绝；无扩展名自动补 `.md`；`uniquePath()` 避免覆盖；使用 `flag: 'wx'` 排他创建 |
| 新建文件夹 | `createFolder(dir, name)` | `mkdir` 非递归（父目录须存在）；同名自动追加序号 |
| 重命名 | `renameEntry(oldPath, newName)` | 名称含 `\ / : * ? " < > \|` 拒绝；目标与原名相同直接返回成功；目标已存在拒绝；成功后**重新注册文件监视** |
| 移动 | `moveEntry(from, toDir)` | `rename` 失败（跨分区 `EXDEV`）时降级为 `cp -r` + `rm -rf`；成功后重新注册监视 |
| 删除 | `removeEntry(target)` / IPC `fs:remove` | IPC 层优先 `shell.trashItem` 送入系统回收站并清理索引；失败降级为 `rm -rf` 物理删除 |
| 唯一路径 | `uniquePath(target)` | 已存在则依次尝试 `name(1).ext`、`name(2).ext`… 最多 9999 次，极端情况追加时间戳 |

### 7.4 外部修改监视

```text
watchFile(filePath)
  · watchers: Map<path, fs.FSWatcher> 去重，已注册则直接返回
  · fs.watch(filePath, { persistent: false }, handler)
      注意 persistent: false —— 监视器不会阻止进程退出
  · handler：仅响应 'change' 与 'rename'
      （部分编辑器采用「删除后重建」的保存方式，必须同时监听 rename）
  · 触发时 broadcastFileChanged(filePath)
      → 向全部存活窗口 webContents.send('fs:file-changed', filePath)
  · watcher.on('error') → 自动取消该监视

unwatchFile / unwatchAll  → 关闭并清理；应用退出时由 before-quit 调用
```

渲染进程收到 `fs:file-changed` 后，结合设置项 `editor.watchExternalChange` 决定是否提示用户重载。

### 7.5 图片保存流水线

```text
渲染进程（main.ts）
  setupPasteHandling()：注册粘贴 Hook（setPasteHook）
     ① 剪贴板含 image/* 文件 → handleImageFile(file, view)
     ② 剪贴板含 text/html 且存在 http(s) 的 <img src>
          · 有选中文字 → 插入 [选中文字](图片URL)
          · 无选中文字 → 插入 ![图片](图片URL)
     ③ 剪贴板为纯文本 URL 且存在选中文字 → 插入 [选中文字](URL)
  bindDragAndDrop()：在 #editor-host 上处理 dragenter/dragover/dragleave/drop
     · 全部事件 preventDefault 阻止 Chromium 默认打开文件行为
     · 图片文件 → 逐张 handleImageFile
     · 非图片文件 → 通过 webUtils.getPathForFile 取真实路径，
       扩展名为 .md/.markdown/.txt/.mdx 时按文档打开
  handleImageFile(file, view)
     · 无文档路径且无工作区 → 提示「请先保存文档或打开工作区，图片需要保存到磁盘」
     · docPath = 当前标签路径 ?? 工作区根目录 ?? ''
     · ext = mimeToExt(file.type)（无 type 时按文件名猜扩展名）
     · image.saveFromBuffer(buffer, ext, docPath)
     · 成功后 insertImage(view, relativePath, 文件名主干作为 alt)
     · Toast：去重命中 → 「图片已存在，直接复用」；否则「图片已保存（宽×高）」

主进程（images.ts）
  saveImageBuffer(data, ext, docPath, originalName)
    1. 读取设置 image.saveMode；为 'url' 时直接返回错误提示（不落盘）
    2. hash = SHA-256(内容)
    3. safeExt = normalizeExt(ext)（补点、小写、白名单校验，非法回退 .png）
    4. targetDir = resolveSaveDir(mode, image.savePath, docPath)
    5. 递归创建 targetDir（失败提示「创建图片目录失败，请检查权限」）
    6. 去重（image.dedupe !== false）：
         findExistingByHash(targetDir, hash)
           查 images 表 WHERE hash = ? AND stored_path LIKE '<dir>%'
           命中的文件若仍存在 → 直接复用（deduplicated: true）
    7. 生成文件名：renderNameTemplate(image.nameTemplate, originalName, safeExt)
    8. avoidCollision()：目标存在且内容不同时追加 -1、-2…；内容相同则复用
    9. 写盘 → 解析宽高 → 插入 images 表 → 记录日志 → 返回结果
  saveImageFromPath(srcPath, docPath)
     · stat 校验是文件；超过 100 MB 跳过（「图片超过 100MB，已跳过」）
     · 读入内容后复用 saveImageBuffer 的全部逻辑
```

**返回结构** `ImageSaveResult`：`{ ok, relativePath?, absolutePath?, width?, height?, deduplicated?, error? }`。

### 7.6 图片命名模板

默认模板：`image-{yyyy}{MM}{dd}-{hhmmss}-{rand}`。

| 占位符 | 展开值 | 示例 |
| --- | --- | --- |
| `{yyyy}` | 四位年份 | `2025` |
| `{MM}` | 两位月份（补零） | `01` |
| `{dd}` | 两位日期（补零） | `09` |
| `{hhmmss}` | 两位时 + 两位分 + 两位秒 | `143805` |
| `{rand}` | 3 字节随机数的十六进制（6 位） | `a3f9c1` |
| `{name}` | 原始文件名（清理 `\ / : * ? " < > \|` 与空白为 `-`，截取前 40 字符；为空时用 `image`） | `屏幕截图` |

**后处理**：

```text
1. 把 \ / : * ? " < > | 替换为 -
2. 去掉开头的连续点号，trim
3. 若结果为空 → image-{时间戳}
4. 若已带受支持的图片扩展名（IMAGE_EXTS 白名单）→ 不再追加扩展名
   否则追加规范化后的扩展名
```

**保存模式**（`resolveSaveDir`）：

| `image.saveMode` | 目录计算 | 写入 Markdown 的路径 |
| --- | --- | --- |
| `relative`（默认） | `dirname(docPath)/<savePath>`，`savePath` 默认 `assets`；若 `savePath` 为绝对路径则直接用 | 以文档目录为基准的相对路径，正斜杠，以 `./` 开头 |
| `docDir` | `dirname(docPath)` | 同上 |
| `absolute` | `savePath`（须为绝对路径，否则以文档目录为基准解析） | 绝对路径，反斜杠统一转为 `/` |
| `url` | 不落盘 | 返回错误提示，由渲染进程告知用户 |

### 7.7 去重与冲突处理

| 机制 | 实现 | 效果 |
| --- | --- | --- |
| 内容去重 | SHA-256 → `images` 表 `hash` 列（有 `idx_images_hash` 索引）→ 校验文件仍存在 | 相同图片只存一份，返回 `deduplicated: true`，UI 提示「图片已存在，直接复用」 |
| 文件名冲突 | `avoidCollision()`：目标存在时先比较内容哈希；相同则复用；不同则依次尝试 `<base>-1.ext`、`<base>-2.ext`… 最多 999 次，兜底追加时间戳 | 绝不覆盖用户已有图片 |
| 大文件保护 | `saveImageFromPath` 超过 100 MB 跳过 | 避免误拖大文件导致内存与磁盘压力 |
| 目录越权 | 扩展名白名单（`IMAGE_EXTS`）+ 保存目录由设置决定 | 不会写入预期之外的位置 |

**支持的图片扩展名**：`.png` `.jpg` `.jpeg` `.gif` `.webp` `.bmp` `.svg` `.avif` `.ico`。

### 7.8 图片尺寸解析

`readImageSize(data: Buffer | string)` 为**零第三方依赖**的纯二进制解析实现，文件路径场景只读取头部 64 KB：

| 格式 | 识别方式 | 尺寸字段 |
| --- | --- | --- |
| PNG | 魔数 `0x89504E47` | IHDR 中的 width（偏移 16）、height（偏移 20），大端 32 位 |
| GIF | 前 3 字节 `GIF` | 逻辑屏幕宽高（偏移 6/8），小端 16 位 |
| BMP | 前 2 字节 `BM` | 偏移 18/22，`height` 取绝对值 |
| WebP | `RIFF` + `WEBP`，按块类型分：`VP8 ` / `VP8L` / `VP8X` | 三种编码各自的位运算解析 |
| JPEG | `FF D8` 起始，扫描 SOF0–SOF15（跳过 DHT `C4`、JPG `C8`、DAC `CC`） | SOF 段中 height（偏移 5）、width（偏移 7），大端 16 位 |
| 其它 | 解析失败 | 返回 `null`，不影响保存流程 |

## 8 导出设计

实现文件：`src/main/services/exporter.ts`（609 行）。全部导出能力基于 Electron 内置机制，**不依赖 Puppeteer、wkhtmltopdf 等外部程序**（Pandoc 为可选的格式转换器）。

### 8.1 导出流程

```text
渲染进程 main.ts
  quickExport(format)
    1. 取当前标签的内容与基名
    2. exporter.pickOutputPath(format, `${baseName}.${ext}`)   ← 弹出保存对话框
    3. 组装 ExportOptions：
         format  目标格式
         docPath 当前文档路径（解析相对图片）
         title   文档名主干
         html    · Pandoc 类格式（docx/latex/epub/rtf）→ 直接传【原始 Markdown】
                 · 其它格式 → buildExportHtml(content, docPath) 生成 HTML 正文
         theme   当前文档主题 ID
    4. exporter.run(options, outputPath)

  buildExportHtml(content, docPath)
    · renderDocument(md, content, { docPath, forExport: true })
    · 用正则找到 <div class="hsm-mermaid" data-mermaid="..."> 占位符，
      逐个调用 renderMermaid(code) 并替换为真实 SVG（保证导出与所见一致）
    · 若有 Front Matter，前置一个折叠块：
        <div class="hsm-front-matter"><div class="hsm-front-matter-title">文档属性</div>
        <pre>…</pre></div>

主进程 exporter.ts
  exportDocument(options, outputPath)
    · 递归创建输出目录
    · 按 format 分派：
        html       → exportHtml         （带样式单文件）
        html-plain → exportHtmlPlain    （纯语义化 HTML）
        pdf        → exportPdf
        png        → exportPng
        docx / latex / epub / rtf → exportViaPandoc
        其它       → { ok:false, error:'暂不支持的导出格式：…' }
    · 每个分支结束都调用 recordExport() 写入 export_history 表
    · 顶层 try/catch：异常时记录失败历史并返回 { ok:false, error }
  IPC 层随后按 export.openAfterExport 决定是否 openExportedFile()
```

**格式与扩展名映射**（`export:pick-output`）：`html` → `HTML 网页 (.html)`、`html-plain` → `HTML 网页（无样式）(.html)`、`pdf` → `PDF 文档 (.pdf)`、`png` → `PNG 图片 (.png)`、`docx` → `Word 文档 (.docx)`、`latex` → `LaTeX 源文件 (.tex)`、`epub` → `ePub 电子书 (.epub)`、`rtf` → `RTF 富文本 (.rtf)`。

### 8.3 PDF 导出

```text
exportPdf(options, outputPath)
  1. html = buildHtmlDocument({ ...options, withStyle: true })
  2. win = createHiddenWindow(pageWidth + 80, 1000)
       · show: false（离屏）
       · webPreferences：contextIsolation true / nodeIntegration false /
         backgroundThrottling false / javascript true / webSecurity true
       · setMenuBarVisibility(false)
  3. loadHtmlIntoWindow(win, html)
       · 写入临时文件 <temp>/hsm-export-<时间戳>-<随机串>.html 后 win.loadFile()
         —— 使用临时文件而非 data: URL，避免超长文档命中 URL 长度限制

         document.fonts.ready、额外 250 ms 以等 Mermaid 等异步渲染完成；
```

**纸张尺寸白名单**（Electron 仅接受固定枚举）：`A3`、`A4`、`A5`、`Legal`、`Letter`、`Tabloid`。`normalizePageSize()` 做大小写不敏感匹配，未命中回退 `A4`。

| 无单位 / 其它 | ÷ 25.4（按毫米处理） |

### 8.4 PNG 长图导出与降采样

```text
exportPng(options, outputPath)
  1. scale = clamp(设置 export.pngScale, 1, 4)         // 默认 2
  2. html = buildHtmlDocument({ ...options, withStyle: true })
  3. win = createHiddenWindow(pageWidth + 80, 1200)
  4. loadHtmlIntoWindow(win, html)
  5. 测量真实内容高度：
       measured = max(document.body.scrollHeight,
                      document.documentElement.scrollHeight, 600)
  6. 计算缩放系数 factor（先满足高度上限，再满足面积上限）：
       width = pageWidth + 80
       height = ceil(measured)
       if (height > MAX_CANVAS_HEIGHT = 16000) factor = 16000 / height
       area = width * height * factor²
       if (area > MAX_CANVAS_AREA = 64 × 1024 × 1024)
            factor = min(factor, sqrt(MAX_CANVAS_AREA / (width * height)))
       factor = max(0.15, factor)                      // 兜底下限
  7. 按缩放后尺寸调整窗口：setContentSize(width × factor, min(目标高度, 16000))
     若 factor < 1 则 setZoomFactor(factor)
  8. 等待 400 ms 让重排完成 → capturePage() → toPNG()
  9. 若 scale > 1 且 factor === 1（说明画布有富余）：
       setZoomFactor(scale) + setContentSize(width × scale, min(height × scale, 16000))
       再等 400 ms → 二次 capturePage() 提升清晰度
 10. 写盘 → recordExport → 返回 { ok, outputPath, fileSize }
 11. finally 销毁隐藏窗口
```

**两个上限常量的作用**：

| 常量 | 值 | 作用 |
| --- | --- | --- |
| `MAX_CANVAS_HEIGHT` | 16000 px | 规避 Chromium 单张画布的高度上限 |
| `MAX_CANVAS_AREA` | 64 × 1024 × 1024（约 6710 万像素） | 控制总像素面积，防止内存暴涨导致渲染进程被 OOM 杀掉 |
| `factor` 下限 | 0.15 | 极端超长文档下也不至于缩得不可读（此时输出长宽约为原尺寸的 15%） |

> 长图导出是「尽力而为」的能力：对超过画布上限的超长文档会主动降采样，宁可略微损失清晰度也不让导出失败。

```text
       「未检测到 Pandoc。导出 Word / LaTeX / ePub / RTF 需要安装 Pandoc
        （免费开源，https://pandoc.org）。安装后重新启动本软件即可自动识别；
         HTML 与 PDF 导出无需 Pandoc。」
  2. 把原始 Markdown 写入临时文件 <temp>/hsm-pandoc-<时间戳>.md
  3. args = [tmpMd, '-o', outputPath, '--standalone',
             `--resource-path=${dirname(options.docPath || '.')}`]
     标题存在时追加 `--metadata=title:{标题}`
     按格式追加 -t：docx → docx；latex → latex；epub → epub3；rtf → rtf
  4. execFileAsync(pandoc, args, { timeout: 120000, maxBuffer: 32 MB })
  5. stat 输出文件 → recordExport → 返回结果
  6. finally 删除临时 Markdown 文件
```

**设计要点**：

- **以原始 Markdown 作为输入**（而非渲染后的 HTML），转换结果更准确、更符合 Pandoc 的语义推断；因此渲染进程在 Pandoc 分支传入的是 `content` 而不是 HTML；
- `--resource-path` 指向文档目录，使相对路径引用的图片能被 Pandoc 正确打包进 docx / epub；
- `--standalone` 生成完整文档（含模板与元数据），否则 docx 会缺少样式骨架；
- 超时 120 秒、输出缓冲 32 MB，覆盖较大文档的转换需求；
- 检测结果被缓存，因此**安装 Pandoc 后需重启软件**才能识别（提示语中已明确说明）。

### 8.6 导出历史与打开

| 环节 | 实现 |
| --- | --- |
| 记录 | `recordExport(options, outputPath, status, errorMsg?)` 向 `export_history` 写入一行；`file_size` 取输出文件 `statSync().size`（文件不存在记 0）；失败分支同样记录 |
| 自动打开 | IPC 层在导出成功后检查 `export.openAfterExport`，为真则 `openExportedFile()` → `shell.openPath()`，失败仅记录日志 |

## 9 快捷键系统设计

### 9.1 命令表

命令表定义在 `src/shared/commands.ts`，是主进程与渲染进程**共用同一份**的契约。

```ts
export type CommandCategory = '文件' | '编辑' | '格式' | '视图' | '表格' | '帮助';

export interface CommandDef {
  id: string;            // 命令唯一标识，如 'format.bold'
  name: string;          // 命令中文名称
  category: CommandCategory;
  defaultKey: string;    // 默认快捷键；空串表示默认不绑定
  description?: string;  // 设置面板提示
}
```

导出的三个常量：

| 常量 | 类型 | 用途 |
| --- | --- | --- |
| `COMMANDS` | `CommandDef[]` | 全部 82 条命令（完整清单见[附录 A](#附录-a命令-id-全表)） |
| `COMMAND_MAP` | `Map<string, CommandDef>` | 命令 ID → 定义，O(1) 查找 |
| `DEFAULT_KEYBINDINGS` | `Record<string, string>` | 命令 ID → 默认组合串，供持久化层判断 `is_default` |

### 9.2 按键组合书写规范

```text
修饰键书写顺序固定为：Mod → Ctrl → Alt → Shift，最后是键名
例如：'Mod+Shift+Z'、'Alt+ArrowUp'、'Shift+Alt+ArrowDown'、'F8'、'Tab'、'Mod+/'
```

| 修饰键 | 含义 |
| --- | --- |
| `Mod` | **跨平台修饰键**：Windows / Linux 上为 `Ctrl`，macOS 上为 `⌘`(Command) |
| `Ctrl` | 始终是 `Control` 键，跨平台含义一致，用于少数需要区分 Ctrl 与 Cmd 的特殊绑定 |
| `Alt` | `Alt`（macOS 上也接受别名 `Option`） |
| `Shift` | `Shift` |

**修饰键别名**：`Mod` 接受 `mod` / `cmd` / `command` / `meta` / `super`；`Ctrl` 接受 `ctrl` / `control`。

### 9.3 解析与匹配

**解析** `parseKeyCombo(combo): ParsedKey | null`：

```ts
interface ParsedKey { mod: boolean; ctrl: boolean; alt: boolean; shift: boolean; key: string; }
```

1. 按 `+` 拆分并 trim，跳过空段；
2. 逐段识别：命中修饰键别名则置位；否则视为主键；
3. 主键归一化（`KEY_ALIASES` 表，约 30 条）：

| 写法 | 归一化为 |
| --- | --- |
| `esc` / `escape` | `Escape` |
| `space` / `spacebar` | `' '` |
| `tab` / `enter` / `return` / `backspace` / `delete` / `del` / `insert` / `home` / `end` | 对应的 `KeyboardEvent.key` 名 |
| `pageup` / `pagedown` | `PageUp` / `PageDown` |
| `up` / `down` / `left` / `right` / `arrowup` … | `ArrowUp` / `ArrowDown` / `ArrowLeft` / `ArrowRight` |
| `backquote` / `minus` / `equal` / `plus` / `bracketleft` / `bracketright` / `backslash` / `semicolon` / `quote` / `comma` / `period` / `slash` | `` ` `` `-` `=` `+` `[` `]` `\` `;` `'` `,` `.` `/` |

4. 单字符主键统一转大写；形如 `F1`–`F12` 的键统一转大写；
5. 主键为空时返回 `null`。

**事件匹配** `matchCombo(e: KeyboardEvent, combo: string): boolean`：

```text
1. parseKeyCombo 失败 → false
2. isMac = /Mac/i.test(navigator.platform || navigator.userAgent)
3. evtMod  = isMac ? e.metaKey : e.ctrlKey
   evtCtrl = isMac ? e.ctrlKey : false
4. 逐项严格比对 mod / ctrl / alt / shift
5. 非 macOS 上按下 Meta（Windows 键）直接返回 false（不作为绑定）
6. 归一化事件键名后与 parsed.key 做大小写不敏感比较
```

**事件转组合串** `eventToCombo(e)`：

- 只按下修饰键本身（`Control` / `Meta` / `Alt` / `Shift` / `CapsLock` / `Dead`）时返回空串——**保证不会把「只按 Shift」记录成绑定**；
- 收集修饰键时按 `Mod → Alt → Shift` 顺序拼接（macOS 上 `metaKey` 记 `Mod`、`ctrlKey` 记 `Ctrl`；其他平台 `ctrlKey` / `metaKey` 均记 `Mod`）；
- 主键经 `normalizeKeyName()` 归一化（空格 → `Space`，单字符转大写）。

**展示格式化** `formatCombo(combo, forMac?)`：

| 平台 | 展示形式 |
| --- | --- |
| Windows / Linux | 用 `+` 连接，修饰键显示为 `Ctrl` / `Alt` / `Shift`，方向键显示为 `↑` `↓` `←` `→`，`Escape` 显示 `Esc`，`Delete` 显示 `Del` |
| macOS | 紧凑连接，`Mod` → `⌘`、`Ctrl` → `⌃`、`Alt` → `⌥`、`Shift` → `⇧` |
| 未绑定（空串） | 「未绑定」 |

**可绑定性校验** `isBindableCombo(combo)`：

```text
解析失败 → false
功能键（F1–F12 等 F\d{1,2}）→ true（允许单独绑定）
其它 → 必须至少含 Mod / Ctrl / Alt 之一，否则 false（避免与普通字符输入冲突）
```

### 9.4 冲突检测

**全量检测** `findConflicts(bindings?)`：

```text
1. 遍历绑定列表，跳过 keybinding 为空的命令（未绑定不参与检测）
2. 用 Map<组合串, 命令ID[]> 聚合
3. 命令数 > 1 的组合即为冲突，输出 { keybinding, commandIds }
```

**单次设置时的冲突检测** `setShortcut(commandId, keybinding)`：

```text
1. 命令 ID 必须存在于 COMMAND_MAP，否则返回 { ok:false, error:'未知命令：…' }
2. combo = keybinding.trim()；为空串 → 直接持久化为「解除绑定」并返回成功
3. isBindableCombo(combo) 为假 → 返回 { ok:false, error:'快捷键必须包含 Ctrl/Cmd、Alt 或为功能键（F1–F12）' }
4. 在现有绑定中查找「其它命令」是否已占用同一组合（大小写不敏感）
     命中 → 返回 { ok:false, conflict:{ keybinding, commandIds:[本命令, …占用者] } }，【不写入】
5. 通过 → persist() 写库并刷新缓存
```

**渲染进程侧的冲突呈现**：设置面板调用 `shortcuts:set`，收到 `conflict` 时展示冲突详情并**阻止保存**（需求 F-62 的验收点）。

### 9.5 持久化

**表结构**：`shortcuts`（见 §4.3.6）。**写入方式**：

```sql
INSERT INTO shortcuts (command_id, command_name, keybinding, is_default, updated_at)
VALUES (?, ?, ?, ?, CURRENT_TIMESTAMP)
ON CONFLICT(command_id) DO UPDATE SET
  keybinding   = excluded.keybinding,
  command_name = excluded.command_name,
  is_default   = excluded.is_default,
  updated_at   = CURRENT_TIMESTAMP;
```

`is_default` 的计算：`keybinding === DEFAULT_KEYBINDINGS[command_id] ? 1 : 0`。

**读取合并** `listShortcuts()`：

```text
1. 命中内存缓存则直接返回副本（深拷贝，避免调用方误改）
2. 读取 shortcuts 表的全部 (command_id, keybinding)
3. 以 COMMANDS 为主表遍历：
     hasCustom = 表中有该 command_id
     binding   = hasCustom ? 表值 : cmd.defaultKey
     customized = hasCustom && binding !== cmd.defaultKey
4. 写入缓存并返回
```

**缓存失效** `invalidateShortcutCache()`：在任何写操作（`persist` / `resetShortcut` / `resetAllShortcuts`）后调用。

**重置**：

| 操作 | 实现 |
| --- | --- |
| 单条重置 | `DELETE FROM shortcuts WHERE command_id = ?`（删除后回落 `defaultKey`） |
| 全部重置 | `DELETE FROM shortcuts` 后返回 `listShortcuts()` |

### 9.6 方案导入导出

**导出** `exportShortcuts()`：

```json
{
  "_comment": "花生苗 Markdown 编辑器 快捷键方案。作者：何飞  微信：6731663",
  "应用": "花生苗 Markdown 编辑器",
  "版本": 1,
  "导出时间": "2025-01-01T00:00:00.000Z",
  "快捷键": [
    { "命令": "加粗", "命令ID": "format.bold", "分类": "格式", "按键": "Mod+B" }
  ]
}
```

默认文件名：`花生苗快捷键方案-YYYY-MM-DD.json`（保存对话框的 `defaultPath`，位于用户主目录）。

**导入** `importShortcuts()`：

```text
1. 弹出打开对话框（过滤器：JSON 文件）
2. 解析 JSON，兼容两种顶层结构：
     · 直接是数组
     · 对象且含 '快捷键' 数组
   都不是 → 返回 { ok:false, error:'文件格式不正确，缺少"快捷键"数组' }
3. 逐条处理：
     id  = item['命令ID'] ?? item['commandId']
     key = item['按键']   ?? item['keybinding']
     · id 为空或不在 COMMAND_MAP 中 → 计入 skipped，跳过
     · 先 DELETE 该命令的旧绑定（避免导入过程中出现自我冲突）
     · setShortcut(id, key)：成功 count++，失败（冲突或非法）计入 skipped
4. 返回 { ok, count, error: skipped.length ? '有 N 条未导入（冲突或非法）：…' : undefined }
5. 解析异常 → 返回 { ok:false, error:'文件解析失败，请确认是本软件导出的 JSON 文件' }
```

### 9.7 渲染进程的按键分发

```text
main.ts 注册全局 keydown 监听（挂在 window / document 上）
  1. e.isComposing 为真 → 直接返回（不打断中文输入法组合过程）
  2. Esc 优先处理：有模态框 → 关闭最上层模态框；查找条可见 → 关闭查找条
  3. resolveCommand(e)（core/store.ts）
       · 用 rebuildKeyIndex() 维护的「组合串 → 命令 ID」索引做 O(1) 查询
       · 命中则返回命令 ID
  4. 命中命令 → e.preventDefault() + e.stopPropagation() + runCommand(commandId)
  5. runCommand 从命令实现表取出回调并执行（含异步命令），返回是否已执行
```

**两个层次的快捷键**：

| 层次 | 注册位置 | 覆盖范围 | 示例 |
| --- | --- | --- | --- |
| **编辑器内部** | `editor.ts` 的 `keymap.of([...])`（CodeMirror 扩展） | 仅在编辑器获得焦点时生效，且优先于 DOM 监听 | `Mod-b`、`Mod-i`、`Mod-1`…`Mod-0`、`Mod-Shift-[`、`Alt-ArrowUp`、`Mod-Shift-d`、`Tab`（`indentWithTab`） |
| **应用级** | `main.ts` 的全局 `keydown` 监听 + `core/store.ts` 的命令索引 | 整个窗口 | 文件操作、视图切换、表格操作、帮助、以及所有被自定义改绑的命令 |

```ts
// editor.ts 的编辑器内 keymap 组合顺序（后注册者优先级更低）
keymap.of([
  ...smartInputKeymap(deps),   // Enter 列表续写、Backspace 删除空列表标记
  ...formatKeymap(),           // 格式化与行操作
  ...historyKeymap,            // 撤销重做
  ...defaultKeymap,            // CodeMirror 默认按键
  indentWithTab,               // Tab 缩进
])
```

**设计取舍**：编辑器内 keymap 使用**硬编码**的 `Mod-b` 形式（而非读取用户自定义绑定），应用级分发则完全走命令表。这保证了「编辑器焦点内的输入体验」与「用户可自定义」两个目标可以并存；代价是自定义绑定对编辑器内 keymap 覆盖的那部分命令不完全生效——这是需要在后续版本统一的地方（见[附录 C-1-3](#c-1-3-编辑器内-keymap-与用户自定义绑定的双轨)）。

### 9.8 `Ctrl+0` 冲突的裁定

需求规格说明书 §4.3 与 §4.4 中，`Ctrl+0` 同时被「普通段落」与「恢复默认字号」占用。本项目的裁定：

| 命令 | 命令 ID | 最终默认绑定 | 依据 |
| --- | --- | --- | --- |
| 普通段落 | `format.paragraph` | **`Mod+0`** | Typora 使用习惯：`Ctrl+0` 取消标题样式、回到正文段落，是高频操作 |
| 恢复默认字号 | `view.zoomReset` | **`Mod+Shift+0`** | 字号恢复属于低频操作，让位给高频的段落切换 |

该裁定同时体现在三处，保证一致：`src/shared/commands.ts` 的命令表注释与定义、`renderer/main.ts` 的「用户手册」内置说明、以及项目文档（README 与用户手册）。macOS 原生菜单中的「普通段落」也绑定为 `Cmd+0`。

## 10 主题系统设计

### 10.1 两层结构与载体选择

**载体选择**：主题以**纯文本形式定义在 TypeScript 中**（`src/shared/themes.ts`），而非独立 `.css` 文件。原因：

1. 渲染进程需要把主题 CSS 注入编辑器，主进程导出 HTML / PDF 时也需要**同一份** CSS——放在共享层可避免两处维护；
2. 打包后无需再关心主题文件的路径与拷贝问题（`src/renderer/themes/` 目录因此保持为空）；
3. 主题内容属于「代码资产」而非「用户资产」，纳入类型系统与构建流程更安全。

**两层结构**：

```text
┌───────────────────────────────────────────────────────────────┐
│ 第一层：结构样式 BASE_DOC_CSS（所有主题共用）                  │
│   标题层级与字号、段落、行内标记、列表、引用、代码、表格、      │
│   公式、图表、容器、脚注、目录、Front Matter、kbd、锚点         │
│   所有颜色与尺寸一律引用 CSS 变量，不写死具体值                 │
└───────────────────────────────┬───────────────────────────────┘
                                │ 变量
┌───────────────────────────────▼───────────────────────────────┐
│ 第二层：配色主题 DOC_THEMES（6 款）                            │
│   只声明 CSS 变量 + 少量特化规则（如去掉 h1 下边框）            │
└───────────────────────────────┬───────────────────────────────┘
                                │
┌───────────────────────────────▼───────────────────────────────┐
│ 第三层：代码高亮主题 CODE_THEMES（5 款）                        │
│   覆盖代码块底色变量 + 逐类定义 Shiki token 颜色          │
└───────────────────────────────────────────────────────────────┘

最终样式 = BASE_DOC_CSS + 主题 CSS + 代码主题 CSS     （buildDocumentCss）
```

**新增主题的成本**：只需提供一组颜色变量（约 21 个），结构样式完全复用。

## 11 性能设计

需求规格说明书 §5.1 给出了明确的性能指标。本章说明当前实现采取的手段与尚未达成的部分。

### 11.1 编辑器渲染：视口虚拟化

CodeMirror 6 原生只渲染视口内（含少量缓冲）的行，长文档的 DOM 节点数不随文档长度线性增长。本项目在此基础上做了三点配合：

| 手段 | 实现 |
| --- | --- |
| 不把渲染结果写回文档 | 全部渲染以装饰器实现，文档模型保持为纯文本，避免「渲染 → 文档变化 → 重新解析」的正反馈 |
| 大块内容用块级 Widget 整体替换 | 代码块、表格、Mermaid、块级公式、分割线、Front Matter 都是单个 Widget，视口内的 DOM 规模可控 |
| 自动换行按设置开关 | `wrapCompartment` 动态切换 `EditorView.lineWrapping`；极大宽文档关闭自动换行可显著降低排版计算量（设置项 `editor.softWrap`） |

### 11.2 装饰器重算策略

`ViewPlugin.update` 中的三重短路保证了「无变化不重算」：

```text
docChanged || selectionSet || viewportChanged || geometryChanged  为假 → 立即返回
```

进一步的两级复用：

| 复用项 | 条件 | 收益 |
| --- | --- | --- |
| 标题列表 | `computeHeadings = contentChanged` | 单纯移动光标（`selectionSet`）时不重复全文扫描标题 |
| 大纲刷新 | 标题签名（`level:line:text|`）比较 | 标题未真正变化时不触发界面刷新 |

**尚未达成的部分**（诚实记录）：`buildDecorations` 目前是**全文档重算**——它会遍历整棵语法树、`doc.toString()` 取全文、并逐行执行公式扫描。文件头部注释所述「所有计算只针对视口范围」是设计目标，当前实现与 §6.7 的「按需重算」并非同一层次：

| 目标 | 现状 | 改进方向 |
| --- | --- | --- |
| 只遍历可见范围 | 遍历整棵语法树 | `tree.iterate({ from, to })` 传入视口范围；或先按 `visibleRanges` 过滤后再进入节点 |
| 只扫描可见行的公式 | 全文档逐行扫描 | 以 `view.visibleRanges` 推导行区间，仅扫描该区间（保留前后各若干行缓冲） |
| 避免整篇 `doc.toString()` | 每次重算都构造全文 | 全文仅在需要（标题提取、`[TOC]` 搜索）时按需获取并缓存；`[TOC]` 可改为基于语法树查找 |

在大文档（10 万字以上）下，这三项是首要优化点；当前实现的按键延迟主要受此影响。

### 11.3 Mermaid 的三级缓存与按需加载

| 机制 | 效果 |
| --- | --- |
| 独立打包 + 动态注入 | Mermaid（约 2 MB）不进入主包，首屏只加载 `renderer.js`；文档中没有图表时从不加载 |
| `loadingPromise` 去重 | 并发触发多次加载只注入一次脚本 |
| `renderCache`（源码 → SVG） | 滚动导致 Widget 重建时**同步**填充，无渲染延迟、无闪烁 |
| `errorCache`（源码 → 错误卡片） | 语法错误的图表不反复重试 |
| `pending`（进行中任务） | 同一图表源码只渲染一次，即使同时出现在多处以 Mermaid 内部 ID 唯一化避免冲突 |
| 缓存上限 80 | 长文档累积的 SVG 不会无限占用内存 |
| 主题切换清空 | `clearMermaidCache()` 保证换肤后图表颜色正确 |

### 11.4 全文检索的索引策略

```text
写入路径：打开文件 / 保存文件 → indexDocument()
  · 受设置 advanced.enableIndex 控制（默认开）
  · 同时写 search_content（UPSERT）与 search_index（先 DELETE 再 INSERT）
查询路径：search(keyword, limit = 50)
  · 通道一 FTS5：仅当关键词是纯 ASCII 且不含 " : * ^ ( ) - 时启用，
      查询形式为 `<kw>*`（前缀匹配），最多取 limit × 4 条，单文件最多收集 10 条命中
  · 通道二 LIKE：对 search_content.content 与 title 做子串匹配
      （关键词中的 \ % _ 会先转义，使用 ESCAPE '\'），最多扫描 5000 个文件，单文件最多 20 条
  · 汇总：按 docPath 分组的命中合并，最终按 (docPath, line) 排序后截取 limit 条
  · 加权：标题命中的文件整体加权（score +1000），行号靠前加权（200 - 行号），
          标题命中但正文无命中时补一条 score 500 的记录
  · 片段：命中行前后各截取 60 字符（SNIPPET_PAD），命中词包 <mark>，输出前做 HTML 转义
重建路径：rebuildWorkspaceIndex(root, onProgress)
  · 递归收集 .md / .markdown / .mdx / .txt
  · 跳过 node_modules、.git、.svn、dist、build、.obsidian、.trash 与隐藏项
  · 每处理 20 个文件通过 search:progress 上报一次进度，结束后上报最终值
```

**索引规模控制**：`MAX_SCAN_FILES = 5000` 是 LIKE 通道的扫描上限，保证超大工作区下搜索不会长时间阻塞主进程（主进程的同步 SQLite 调用会阻塞 IPC，因此必须有硬上限）。

### 11.5 主进程侧的规模保护

| 位置 | 保护措施 | 目的 |
| --- | --- | --- |
| 目录树 | 单层最多 2000 个节点 | 防止超大目录（如含数万文件的 `Downloads`）拖死界面 |
| 目录树 | 默认深度 3，`depth <= 0` 不展开 | 惰性展开，避免一次性遍历整个磁盘树 |
| 目录树 | 忽略 `node_modules`、`.git` 等 | 避免把源码仓库的依赖目录当作笔记内容 |
| 全文搜索 | 单次最多扫描 5000 文件、单文件最多 20 条命中 | 控制主进程阻塞时长 |
| 图片 | 单张来源上限 100 MB | 控制内存占用 |
| 历史快照 | 每篇文档最多 50 条（可配 5–500） | 控制数据库体积 |
| 最近文件 | 默认 30 条（可配 5–200） | 控制表体积与菜单长度 |
| 长图导出 | 最大高度 16000 px、最大面积 64 MP、降采样下限 0.15 | 规避 Chromium 画布上限与 OOM |
| 日志 | 单条最长 8000 字符、最多保留 7 天 | 防止日志文件无限增长 |
| 正则查找计数 | 上限 9999 次 | 防止极端情况下长时间占用 |

### 11.6 数据库性能

| 手段 | 说明 |
| --- | --- |
| WAL 日志模式 | 读写并发更友好，且崩溃恢复更安全 |
| `synchronous = NORMAL` | 在安全与写入速度之间取平衡（WAL 下 `NORMAL` 不会因进程崩溃丢数据，仅在系统崩溃时可能丢最后几个事务） |
| `temp_store = MEMORY` | 排序与临时表驻内存，加速搜索与分组 |
| 预编译语句缓存 | `stmtCache: Map<sql, StatementSync>` 避免重复解析同一 SQL |
| 关键索引 | `idx_documents_path`、`idx_documents_updated`、`idx_versions_doc`、`idx_images_hash`、`idx_search_content_title` |
| 设置与快捷键内存缓存 | `getAllSettings()` 与 `listShortcuts()` 均带缓存，避免高频读取打库；写操作后失效 |
| 关闭前 checkpoint | `PRAGMA wal_checkpoint(TRUNCATE)` 把 WAL 合并回主库，避免 WAL 无限增长 |

### 11.7 定时任务与防抖

| 任务 | 触发方式 | 参数 |
| --- | --- | --- |
| 自动保存 | 内容变化后延迟 `general.autoSaveInterval`（默认 5 秒，范围 1–600） | 每次输入都会重置定时器（防抖）；窗口 `blur` 立即保存；另有 30 秒兜底轮询 |
| 版本快照 | 定时器延迟 `advanced.historyInterval`（默认 5 分钟，范围 1–120），执行后重新排程 | 仅对已命名文档生效 |
| 窗口状态保存 | `resize` / `move` 后 600 ms 防抖 | 避免拖动窗口时频繁写库 |
| 打字机滚动 | `requestAnimationFrame` 中执行 | 偏移小于 8 px 不滚动，避免抖动 |
| 长图导出等待 | 固定 400 ms + 资源等待（图片最长 4 秒 / 整体 8 秒） | 保证重排与资源加载完成 |

### 11.8 已识别的性能风险

| 风险 | 影响 | 缓解/建议 |
| --- | --- | --- |
| 装饰器全文档重算（§11.2） | 大文档按键延迟随文档长度增长 | 按视口范围遍历语法树与扫描公式 |
| `doc.toString()` 每次重算调用 | 构造 10 万字符字符串的拷贝开销 | 改为按需获取并缓存 |
| 主进程同步 SQLite | 大工作区搜索会短暂阻塞 IPC 响应 | 已有 5000 文件上限；后续可移至 Worker 或分批异步 |
| 全文搜索 LIKE 通道无索引 | 5000 文件 × 全文扫描为 O(n·m) | 中文场景考虑按字分词的 FTS5 `trigram` 分词器（SQLite 3.34+ 支持） |
| 窗口几何设置读写类型不一致 | 窗口位置尺寸记忆失效（见附录 C-1-1） | 把 `window.*` 纳入 `SETTING_DEFS` 或改用独立的窗口状态存储 |

## 12 打包与分发设计

### 12.1 构建流程

构建脚本 `scripts/build.mjs`（esbuild）一次产出五类产物并拷贝静态资源：

```text
buildAll()
  1. 清空 dist/
  2. 顺序构建 5 个目标（各自输出耗时）
  3. copyStatic()：
       · src/renderer/index.html → dist/renderer/index.html
       · resources/             → dist/resources/（存在时）
       · LICENSE / THIRD-PARTY-LICENSES.md / README.md → dist/（开源合规）
  4. 输出产物体积速览（main.js / preload.js / renderer.js / mermaid.js / renderer.css）
```

| 目标 | 入口 | 输出 | 格式 | 平台 | 目标语法 |
| --- | --- | --- | --- | --- | --- |
| 主进程 | `src/main/main.ts` | `dist/main/main.js` | CommonJS | node | node20 |
| 预加载脚本 | `src/preload/preload.ts` | `dist/preload/preload.js` | CommonJS | node | node20 |
| 渲染进程脚本 | `src/renderer/main.ts` | `dist/renderer/renderer.js` | IIFE | browser | chrome120 |
| Mermaid 按需包 | `src/renderer/editor/mermaid-entry.ts` | `dist/renderer/mermaid.js` | IIFE | browser | chrome120 |
| 样式表 | `src/renderer/styles/index.css` | `dist/renderer/renderer.css` | IIFE | browser | chrome120 |

**关键配置**：

| 配置 | 值 | 原因 |
| --- | --- | --- |
| `external: ['electron']` | 仅主进程与预加载 | Electron 由运行时提供，不能打进 bundle |
| `bundle: true` | 全部目标 | 单文件产物，便于 asar 打包与快速加载 |
| 渲染进程 `format: 'iife'` | — | 页面通过 `file://` 加载，Chromium 会以 CORS 策略拦截 `file://` 下的 ESM `import` |
| `minify: !WATCH` | — | 监听模式保留可读代码与内联 sourcemap，便于调试 |
| Mermaid 包强制 `minify: true` | — | 体积最大，任何模式下都压缩 |
| `loader: { '.woff2': 'file', '.woff': 'file', '.ttf': 'file' }` + `assetNames: 'fonts/[name]-[hash]'` | — | KaTeX 等字体按文件资源输出到 `dist/renderer/fonts/` |
| `define` 注入 | `__APP_VERSION__` / `__APP_NAME__` / `__APP_AUTHOR__` / `__APP_CONTACT__`（`'微信 6731663'`）/ `__APP_HOMEPAGE__` / `__BUILD_TIME__` | 版本与作者信息只在 `package.json` 维护一处，构建期替换为字面量 |

**监听模式** `--watch`：为每个目标创建 esbuild context 并 `watch()`，同时用 `fs.watch` 监听 `index.html` 变更并同步拷贝（esbuild 不处理 HTML 入口）。

**依赖安装加速**：`.npmrc` 配置了国内镜像（`registry.npmmirror.com`）、Electron 二进制镜像（`electron_mirror`）、electron-builder 二进制镜像（`electron_builder_binaries_mirror`），并关闭 `audit` 与 `fund` 提示。

## 13 安全设计

### 13.1 进程隔离与最小权限

| 措施 | 实现位置 | 说明 |
| --- | --- | --- |
| 上下文隔离 | `window.ts` `contextIsolation: true` | 预加载与页面脚本分处不同 JS 上下文 |
| 关闭 Node 集成 | `window.ts` `nodeIntegration: false` | 页面无法 `require`、无 `process` |
| 白名单桥接 | `preload.ts` | 仅通过 `contextBridge.exposeInMainWorld('hsm', api)` 暴露受控 API；不暴露 `ipcRenderer`、不暴露任何 Node 原生对象、不传递函数 |
| 无原生模块 | `database.ts` 使用 `node:sqlite` | 不引入需要本地编译的第三方二进制，减少供应链与构建风险 |

> `sandbox: false` 是有意为之：本项目预加载脚本需要使用 `webUtils` 等能力；安全边界由「最小暴露 + 严格 CSP + 路径校验」共同构成，而非依赖渲染器沙箱。

### 13.2 内容安全策略（CSP）

`src/renderer/index.html` 中的 `<meta http-equiv="Content-Security-Policy">` 完整内容：

```text
default-src 'self';
script-src 'self';
style-src 'self' 'unsafe-inline';
img-src 'self' file: data: blob:;
font-src 'self' data:;
media-src 'self' file: data: blob:;
connect-src 'self';
frame-src 'none';
object-src 'none';
base-uri 'none';
form-action 'none';
```

| 指令 | 取值 | 设计理由 |
| --- | --- | --- |
| `default-src` | `'self'` | 默认只允许加载应用自身资源 |
| `script-src` | `'self'` | **禁止内联脚本与 eval**，杜绝 Markdown 内容引发的脚本执行 |
| `style-src` | `'self' 'unsafe-inline'` | 主题 CSS 是运行期动态注入的，必须允许内联样式（样式注入不构成脚本执行风险） |
| `img-src` | `'self' file: data: blob:` | 允许显示本地图片、`data:` 内联图与粘贴产生的 `blob:` |
| `font-src` | `'self' data:` | KaTeX 字体来自应用资源或内联 data URL |
| `media-src` | `'self' file: data: blob:` | 预留音视频引用能力 |
| `connect-src` | `'self'` | **禁止任何对外网络请求**，与「完全离线、不上传数据」一致 |
| `frame-src` / `object-src` | `'none'` | 禁止嵌入外部页面与插件 |
| `base-uri` | `'none'` | 防止通过 `<base>` 劫持相对路径 |
| `form-action` | `'none'` | 禁止表单提交跳转 |

### 13.3 窗口、导航与外部链接

| 措施 | 实现 |
| --- | --- |
| 拒绝新建窗口 | `webContents.setWindowOpenHandler` 一律返回 `{ action: 'deny' }`；若 URL 是 `http(s)` 则交给系统默认浏览器 |
| 阻止外部导航 | `will-navigate` 中拦截非 `file://` / `devtools://` 的导航，`http(s)` 交给系统浏览器 |
| 禁止 webview | `app.on('web-contents-created')` 中 `will-attach-webview` 一律 `preventDefault()` |
| 拒绝权限请求 | `session.setPermissionRequestHandler((_wc, _permission, cb) => cb(false))`，摄像头 / 麦克风 / 地理位置等一律拒绝 |
| 外部链接协议白名单 | IPC `shell:open-external` 仅允许 `^(https?\|mailto):`，其余静默忽略 |
| 单实例 | `requestSingleInstanceLock()` 防止多实例并发写数据库 |

### 13.4 IPC 层校验

| 措施 | 实现 |
| --- | --- |
| 路径校验 | `assertPath(p)`：必须是非空字符串，且 `path.resolve()` 规范化后使用；拒绝相对路径与空值 |
| 错误隔离 | 所有可能抛异常的处理器用 `fail(e)` 包装返回 `{ ok:false, error }` 并记录日志 |
| 参数类型收敛 | 字符串参数统一 `String(...)` 转换，数值参数统一 `Number(...)`，布尔参数统一 `Boolean(...)`，避免原型污染类问题 |
| 未知通道 | `ipcMain.on('__unknown__')` 兜底返回 `null`，避免渲染进程悬挂等待 |
| 最小必要原则 | 渲染进程拿到的能力全部是「业务语义」而非「系统语义」（例如没有通用的「执行 Shell 命令」通道） |

### 13.5 数据层安全

| 措施 | 实现 |
| --- | --- |
| 全部使用预编译语句 | `run` / `get` / `all` 均通过 `db.prepare(sql)` + 占位符绑定参数 |
| LIKE 通配符转义 | 搜索关键词中的 `\` `%` `_` 先转义，并使用 `ESCAPE '\'` |
| 动态表名白名单 | `db:info` 中的表名来自代码内固定常量数组，不由用户输入拼接 |
| 数据不落明文敏感信息 | 数据库仅存储文档路径、内容快照、设置与快捷键，不含任何凭据 |

### 13.6 渲染层安全

| 措施 | 实现 |
| --- | --- |
| 不解析原始 HTML | markdown-it `html: false`，用户文档中的 `<script>`、`<iframe>` 等按纯文本输出 |
| 输出统一转义 | 代码块内容经 `escapeHtml()`；搜索片段、标题锚点、容器标题、KaTeX 错误提示、导出页脚等所有插入点均转义 |
| KaTeX 关闭可信命令 | `renderMath` 使用 `trust: false`，禁止 `\href`、`\htmlId` 等 |
| Mermaid 严格模式 | `mermaid.initialize({ securityLevel: 'strict' })`；其渲染结果经 Mermaid 内置的 DOMPurify 消毒后才注入 |
| Mermaid 占位符编码 | 代码内容以 `encodeURIComponent` 存入 `data-mermaid` 属性，避免属性注入 |
| 图片地址解析受限 | `resolveResourceUrl` 仅把 `http(s)` / `data` / `blob` / `file` 及本地绝对/相对路径转为可显示地址；无文档路径时不解析相对路径 |
| 搜索片段转义 | `buildSnippet` 对命中行的前后文与命中词做 HTML 转义后再包裹 `<mark>` |

### 13.7 数据隐私

| 声明 | 实现依据 |
| --- | --- |
| 默认不上传任何用户数据 | CSP `connect-src 'self'` 禁止对外请求；代码中不存在任何网络请求逻辑 |
| 完全离线可用 | 编辑、检索、导出（HTML / PDF / PNG）全部基于本地能力；仅 Pandoc 为本地子进程 |
| 数据仅存本机 | 全部持久化落在 `app.getPath('userData')` 下的 `huashengmiao.db`、`logs/`、`themes/` |
| 无账号体系 | 不存在登录、同步、遥测与埋点代码 |
| 删除可恢复 | 文件删除优先进入系统回收站；版本快照默认开启且保留 50 条 |

### 13.8 日志安全

| 措施 | 实现 |
| --- | --- |
| 落盘位置 | `<userData>/logs/huashengmiao-<YYYY-MM-DD>.log` |
| 按天切分 | 文件名含日期，字典序即时间序 |
| 保留策略 | 最多 7 个文件，超出时删除最早的 |
| 单条限长 | 超过 8000 字符截断并标注 `…(已截断)` |
| 写入容错 | 日志目录不可写时静默降级（`logDir = ''`），绝不影响主流程 |
| 全局异常捕获 | `uncaughtException` 与 `unhandledRejection` 均写入日志 |
| 渲染进程崩溃 | `render-process-gone` 记录原因与退出码 |
| 隐私提示 | 日志可能包含文件路径，用户主动提供日志时请注意其中的个人信息 |

### 14.5 常见构建问题

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| `Cannot find module 'electron'` | 依赖未安装或 Electron 二进制下载失败 | 删除 `node_modules` 重装；确认 `.npmrc` 中的 `electron_mirror` 可用 |
| 渲染进程报 `import` 语法错误 / CORS | 渲染进程被误配为 ESM | 保持 `format: 'iife'`（`file://` 下不能用 ESM） |
| 样式丢失 | `index.css` 中的 `@import "katex/dist/katex.min.css"` 未被解析 | 确认该文件由 esbuild 处理（它是 `renderer.css` 的构建入口） |
| 图表不显示且控制台报 404 | `dist/renderer/mermaid.js` 未生成 | 确认构建目标「Mermaid 按需包」的入口文件存在且构建成功 |
| 字体 404 | 字体资源未输出到 `dist/renderer/fonts/` | 检查 `browserCommon.loader` 与 `assetNames` 配置 |
| 打包后读取 KaTeX 样式失败 | `require.resolve('katex/dist/katex.min.css')` 在 asar 中不可解析 | 代码已对失败做降级（公式以纯文本导出）；如需彻底解决，把 `katex/dist` 加入 `asarUnpack` |
| `npm run dist:*` 报缺少图标 | `build/` 目录为空 | 放置 `icon.ico` / `icon.png` 与 electron-builder 配置（见 §12.2） |

### C.1 仍存在的实现细节问题

以下条目为核对中确认**当前仍然存在**的实现细节，均不影响核心功能的可用性，建议在后续版本处理。

#### C-1-1 窗口几何记忆读取失效

**现象**：窗口位置与尺寸无法在下次启动时恢复。

**根因**：`window.ts` 通过 `setSetting('window.width', b.width)` 等方式写入窗口几何，但
`window.width` / `window.height` / `window.x` / `window.y` / `window.maximized` **都不在**
`SETTING_DEFS` 中。`settings.ts` 的 `getAllSettings()` 对「未知键」原样保留字符串
（`result[row.key] = row.value ?? ''`），而 `resolveWindowBounds()` 使用
`getSetting<number>('window.width', DEFAULT_WIDTH)` 读到的是字符串 `'1280'`；
由于 `Number.isFinite('1280') === false`（`Number.isFinite` 不做类型转换），
判定失败后回退默认尺寸与居中位置。

**影响**：不影响功能正确性，仅影响体验（每次启动都是默认尺寸与居中位置）。

**建议方案（择一）**：

1. 在 `SETTING_DEFS` 中增加 `window.*` 条目（`type: 'number'` / `'boolean'`），使 `coerceSetting` 正确转换类型；
2. 为窗口几何单独建表或复用 `session_state`，避免与面向用户的设置混在一起；
3. 在 `resolveWindowBounds()` 中显式 `Number(...)` 转换后再判断（最小改动，但保留「设置表中存在未定义键」的隐患）。

#### C-1-2 `db:vacuum` 的语义与命名不符

**现象**：IPC 通道名为 `db:vacuum`，但处理器内部调用的是 `closeDatabase()`（执行
`PRAGMA wal_checkpoint(TRUNCATE)` 后关闭连接），并未执行 SQLite 的 `VACUUM` 语句；日志文本为「数据库已压缩整理」。

**影响**：达到了「整理 WAL、回收空间」的效果（下次访问会自动重建连接），但不会重排主数据库文件、
也不会回收已删除数据占据的空闲页。

**建议**：若要真正压缩数据库文件，应在重建连接后单独执行 `database.exec('VACUUM')`；
同时把通道名或日志文本调整为与实际行为一致（例如改名为 `db:checkpoint`）。

#### C-1-3 编辑器内 keymap 与用户自定义绑定的双轨

**现象**：`editor.ts` 的 `formatKeymap()` 与 `smartInputKeymap()` 使用硬编码键位
（`Mod-b`、`Mod-1`…`Mod-0`、`Alt-ArrowUp`、`Mod-Shift-d`、`Mod-Shift-[` 等），不读取用户自定义绑定。

**影响**：用户修改这些命令的快捷键后，在编辑器获得焦点时按键仍会命中编辑器内 keymap，
自定义绑定被忽略。

**建议方案（择一）**：

1. 编辑器内 keymap 改为在 `buildEditorExtensions()` 中依据当前绑定动态生成；
2. 把编辑器内 keymap 精简为「纯输入相关」（Enter / Backspace / Tab / 方向键），格式化命令全部交给应用级分发；
3. 在用户修改绑定后调用 `rebuildEditorState()` 重建编辑器状态以应用新 keymap。

#### C-1-4 装饰器仍为全文档重算

**现象**：`live-preview.ts` 的 `buildDecorations()` 遍历整棵语法树、调用 `doc.toString()` 取全文，
并逐行执行公式扫描（`for (let i = 1; i <= doc.lines; i += 1)`）。
文件头注释所述「所有计算只针对视口范围」尚未实现。

**影响**：大文档（10 万字以上）下每次按键的重算成本随文档长度增长，是 §11.8 中列出的首要性能风险。

**建议**：按 §11.2 的表格实施视口化——`tree.iterate({ from, to })` 限定范围、按 `view.visibleRanges`
推导行区间后仅扫描该区间、全文按需获取并缓存。

#### C-1-5 `file.exportDialog` 未登记进命令表

**现象**：`renderer/main.ts` 通过 `registerCommand('file.exportDialog', …)` 注册了导出格式选择对话框，
但该命令**不在** `COMMANDS` 中。

**影响**：无法被用户自定义快捷键，也不会出现在「快捷键查询」面板与设置面板的命令列表中。

**建议**：补入 `COMMANDS`（分类「文件」，默认不绑定），使其可被快捷键与菜单触发。

#### C-1-6 全文检索的中文分词局限

**现象**：FTS5 使用 `unicode61` 分词器，对「中文连写无空格」的长句支持有限。

**当前缓解**：已通过 `search_content` 原文表 + `LIKE` 子串匹配的兜底通道保证中文可搜索（双通道取并集）。

**建议**：评估 FTS5 的 `trigram` 分词器（SQLite 3.34+ 支持，专为子串匹配设计）或引入轻量中文分词，
以在保持中文命中率的同时恢复索引级查询性能（当前 LIKE 通道为 5000 文件上限的全表扫描）。

#### C-1-7 其他一致性观察

### D.2 CodeMirror 6 的块级装饰限制（重要架构修正）

**问题**：CodeMirror 6 有一条硬性约束——**块级装饰不能由 `ViewPlugin` 提供**
（运行时会抛出 `RangeError: Block decorations may not be specified via plugins`）。

**修正方案**：把实时渲染拆成两个扩展协同工作：

| 扩展 | 类型 | 职责 |
| --- | --- | --- |
| `blockWidgetField` | `StateField<DecorationSet>` | 代码块、表格、块级公式、分割线、Front Matter 的**整块替换**（`Decoration.replace({ block: true })`） |
| `livePreview` | `ViewPlugin` | 行级样式（标题/引用/列表）、行内标记（加粗/斜体/链接/行内代码）、行内 Widget（图片、行内公式、任务复选框、目录） |

块级元素的识别不依赖语法树，而是对文档文本做一次逐行扫描
（`scanBlocks()`，支持围栏代码块、`$$…$$`、GFM 表格、分割线、YAML Front Matter），
扫描结果按 `Text` 对象缓存，因此**仅移动光标时不会重新扫描**。

### D.6 交付后修复：查找 / 替换浮层无法关闭

**现象**：用户报告「查找、替换窗口始终在最上面，无法关闭，所以也就无法编辑文档」。

**根因**：这是一个**系统性的 CSS 缺陷**，而非查找条自身的逻辑问题。

浏览器默认样式表中 `hidden` 属性只对应一条 `[hidden] { display: none }` 规则，
它属于 **UA 样式表**，优先级低于任何作者样式。而本项目的样式表里写着：

```css
.findbar { display: flex; }   /* 作者样式，压过 UA 的 [hidden] 规则 */
```

于是 `element.hidden = true` **完全失效**——元素照样显示。由此产生三个连锁后果：

1. 应用一启动，查找条就已经渲染在编辑区右上角；
2. 点击 ✕（其实现调用 `closeFindBar()`，内部执行 `bar.hidden = true`）没有任何视觉效果；
3. `Ctrl+F` 会把焦点移入查找输入框，而浮层又关不掉，导致后续按键全部进入查找框，
   用户因此「无法编辑文档」。

同一原因还影响其它依赖 `hidden` 属性的元素：替换输入行、状态栏（关闭「显示状态栏」后）、
标题栏的未保存圆点等。

**修复**：在 `src/renderer/styles/base.css` 的全局重置段落中明确 `hidden` 的最高优先级：

```css
[hidden] {
  display: none !important;
}
```

**回归防护**：新增 3 条端到端用例守住这类问题，并已加入常跑测试集：

| 用例 | 断言内容 |
| --- | --- |
| 查找条默认隐藏，可打开也可关闭 | ① 启动时不可见；② `Ctrl+F` 后可见且替换行隐藏；③ 点击 ✕ 后重新隐藏；④ `Ctrl+H` 后两行都可见；⑤ `Esc` 可关闭 |
| 查找条不遮挡编辑区 | 浮层占正文面积 < 20%，关闭后向文档输入文字能正确落盘 |
| 所有 `hidden` 元素确实不可见 | 遍历页面上全部带 `hidden` 属性的元素，只要有一个仍被渲染即判定失败——这条用例可从机制上防止同类问题复发 |

**验证结果**（在**最终安装包**的应用中实测）：

| 检查项 | 结果 |
| --- | --- |
| 启动时查找条可见 | 否 ✅ |
| `Ctrl+F` 后可见 | 是 ✅ |
| 点击关闭后已隐藏 | 是 ✅ |

### D.7 交付后修复：光标可见性与块级元素点击

#### D.7.1 空行与文末无法绘制光标

**现象**：点击空行或文档末尾时看不到光标。

**根因**：样式表中有一条 `.cm-line br { display: none; }`。
CodeMirror 用 `<br>`（`LineBreak` 组件）作为空行的占位元素，
并依赖它的布局信息计算光标矩形（`RectangleMarker.forRange` 中
`view.coordsAtPos()` 返回空则**直接放弃绘制**）。
隐藏 `<br>` 后空行的 `coordsAtPos` 恒为 `null`，光标因此永远画不出来。

实测证据（同一份文档、注入 `display: inline` 前后对比）：

| 行 | 修复前 | 修复后 |
| --- | --- | --- |
| 第 1 行「第一行」 | 161~178 | 161~178 |
| 第 2 行（空行） | **null** | 188~205 |
| 第 3 行「第三行」 | 215~232 | 215~232 |
| 第 4 行（空行） | **null** | 243~260 |

**修复**：移除该规则，并在原处写明原因与后果，防止被当成"多余样式"再次加回。

#### D.7.2 点击块级 Widget 无法定位

**现象**：点击渲染后的代码块中部，光标跑到块外面（CodeMirror 对原子替换区间只会取最近边界）。

**修复**：在编辑器宿主元素上以**捕获阶段**监听 `mousedown`，
命中块级 Widget 时按点击的几何位置换算源码落点，再显式派发选区：

| 块类型 | 定位方式 |
| --- | --- |
| 代码块 | 按 `pre` 的行高换算到第几行，按字符宽（Canvas `measureText`）换算到第几列 |
| 表格 | 找到被点单元格的行列序号，映射到源码行的对应单元格内容起始处 |
| 公式 / 图表 / 分割线 / Front Matter | 定位到块首 |

内部的交互元素（任务复选框、表格浮动工具条、Front Matter 折叠标题）不接管，
交给它们自己处理。

### D.8 交付后修复：坐标映射与代码主题

#### D.8.1 鼠标点击定位整体偏一行（重要）

**现象**：点击第 2 行「你好」，光标却落到第 3 行。

**根因**：行级装饰用 `margin` 制造纵向间距。实测数据：

```
序号 0  h1  top=177  高=42.0   → 底边 219
序号 1  h2  top=235  高=34.5   → 与上一行间隔 16.0px（= .65em × 24.8px）
序号 2  h3  top=282  高=28.1   → 与上一行间隔 12.5px（= .6em  × 20.8px）
```

CodeMirror 的位置模型假定 `.cm-line` 之间**首尾相接**，
它按各行盒高累加出"第 y 像素对应文档哪个位置"。
而 `margin` 不在行盒内，模型与实际布局因此错位，点击坐标整体下移一行。

**修复**：行间距一律改用 `padding`；同时因为 CodeMirror 基础主题自带
`.ͼ1 .cm-line { padding: 0 2px 0 6px }`（特异性 0,2,0，高于单类选择器的 0,1,0），
**所有作用在 `.cm-line` 上的 `padding` 都必须加 `!important`** 才能生效。
修复后实测：

| 行 | 行盒 | 点击行中线时 `posAtCoords` | 真实点击落点 |
| --- | --- | --- | --- |
| `# 你好` | 156~228 | 第 1 行 | 第 1 行第 3 列 |
| `## 你好` | 228~284 | 第 2 行 | 第 2 行第 4 列 |
| `### 你好` | 284~325 | 第 3 行 | 第 3 行第 5 列 |
| 代码块第 2 行 | — | — | 第 6 行 `a = 10` |

#### D.8.2 代码高亮主题在编辑器内不生效

**现象**：代码块配色难看、且切换「代码块高亮主题」没有任何变化。

**根因**（两个叠加）：

1. 主题样式表只作用于 `.hsm-preview`（导出 HTML 的根容器），
   而编辑器里的代码块是 `.hsm-codeblock`，两者不在同一作用域；
2. 编辑器样式表中直接写死了 107 行 `hljs` 配色（一套深色值），
   既与用户选择的主题无关，也谈不上可维护。

**修复**：

- `themes.ts` 新增 `buildEditorCodeCss()`，用同一份配色生成编辑器作用域的样式，
  由 `applyDocumentTheme()` 注入 —— 编辑与导出两处颜色保证完全一致；
- 移除样式表里写死的 107 行配色，只保留一句注释说明配色来源。

修复后实测（切换设置面板里的下拉框，读取代码块的实际计算样式）：

| 主题 | 代码块背景 | 正文色 |
| --- | --- | --- |
| GitHub | `rgb(246, 248, 250)` | `rgb(31, 35, 40)` |
| Dracula | `rgb(40, 42, 54)` | `rgb(248, 248, 242)` |
| Monokai | `rgb(39, 40, 34)` | `rgb(248, 248, 242)` |
| One Dark | `rgb(40, 44, 52)` | `rgb(171, 178, 191)` |
| Solarized Light | `rgb(253, 246, 227)` | `rgb(101, 123, 131)` |

#### D.8.3 行首前缀类快捷键的光标落点

**现象**：按 `Ctrl+1` 后看到 `|# 标题`，期望 `# |标题`。

**根因**：`toggleLinePrefix()` 与 `applyOrderedList()` 派发变更时**没有显式重映射选区**，
CodeMirror 的游标 `assoc` 默认为 **-1**，在"插入点恰好等于光标位置"时会把光标留在插入内容**之前**。

**修复**：新增 `dispatchLineChanges()`，用 `ChangeSet.mapPos(pos, 1)`（assoc = 1）显式映射选区。
实测：`# `→列 2、`## `→列 3、`### `→列 4、`###### `→列 7、`> `→列 2、`- `→列 2、`1. `→列 3、`- [ ] `→列 6。

### D.9 交付后改进：代码高亮引擎升级为 Shiki

**现象**：用户反馈「代码框中各种语言的关键字、变量、符号等信息区分不明显」。

**实测定位**：用 Shiki 渲染用户给出的 Python 片段，输出如下：

```
<span class="hljs-built_in">print</span>(你好)
a = <span class="hljs-number">10</span>
b = a
c = <span class="hljs-string">"this is demo"</span>
```

整段代码只产生 **3 个 token**；变量 `a` `b` `c`、运算符 `=`、括号 `()` 全部是默认文字色。
这是 Shiki 的 Python 语法**本身分类太粗**，调整配色无法解决，必须更换分词引擎。

**方案**：改用 **Shiki**（与 VS Code 使用相同的 TextMate 语法），并做出两个关键决策：

1. **不使用内置主题，改为按作用域自行配色**
   即便是 VS Code 官方主题，`variable.other` 也常常被显式设回正文色
   （github-light 中 `variable` 是橙色，但紧接着 `variable.other` 又被设成 `#24292e`），
   普通变量因此依然"看不见"。本项目直接按作用域给出稳定且拉得开的配色，
   并与 `src/shared/themes.ts` 共用同一份调色板。

2. **按需加载 + 热升级**
   Shiki 与本项目其它依赖不同：它需要异步初始化语法引擎。
   因此单独打成 `dist/renderer/shiki.js`（2.5 MB），
   首帧仍由 Shiki 渲染（用户立刻能看到高亮，不会先白后彩），
   引擎就绪后通过**高亮引擎版本号**触发代码块 Widget 重建，自动升级为精细结果。
   代码块 Widget 的 `eq()` 中加入了版本号比较，版本变化即重建 DOM。

**修复后实测**（同一段 Python 代码）：

| 语法成分 | 颜色 | 说明 |
| --- | --- | --- |
| 关键字 `def` `import` | `rgb(207,34,46)` | 红色粗体 |
| 函数名 `greet` | `rgb(130,80,223)` | 紫色 |
| 变量 `name` `count` | `rgb(149,56,0)` | 橙色 |
| 运算符 `=` | `rgb(27,124,131)` | 青色 |
| 标点 `(` `,` `):` | `rgb(87,96,106)` | 灰色 |
| 数字 `3` | `rgb(5,80,174)` | 蓝色 |
| 字符串 `"hi"` | `rgb(10,48,105)` | 深蓝 |
| 注释 | `rgb(110,119,129)` | 灰色斜体 |

同一段代码共产生 21 个分词、**7 种互不相同的颜色**。

**踩坑记录**：Shiki 的主题对象中一旦存在 `settings` 字段，**`tokenColors` 会被完全忽略**，
所有 token 退化为默认前景色。由于 `ThemeRegistrationRaw` 类型恰好要求 `settings` 存在，
这里只能使用类型断言绕开，并在代码中显著标注，避免后人"好心补全字段"而破坏配色。
