## 二、核心能力实现情况

### 2.1 Typora 式实时渲染（P0 核心）

采用 **CodeMirror 6 装饰器**方案实现，拆分为两个协同扩展：

| 扩展 | 类型 | 职责 |
| --- | --- | --- |
| `blockWidgetField` | `StateField` | 代码块、表格、块级公式、分割线、Front Matter 的整块替换 |
| `livePreview` | `ViewPlugin` | 行级样式、行内标记（加粗/斜体/链接/行内代码）、行内 Widget（图片、行内公式、任务复选框、目录） |

> 之所以必须拆分，是因为 CodeMirror 6 有一条硬性约束：**块级装饰不能由 `ViewPlugin` 提供**。
> 详见《详细设计说明书》附录 D.2。

交互规则：**光标或其所在选区的元素显示源码，其余元素显示渲染结果**。
块级元素的结束位置采用半开区间判定，因此光标停在代码块/表格/分割线之后的下一行行首时，
不会突兀地退回源码。

## 四、构建与使用

### 4.1 环境要求

只需要 **Node.js 18 及以上**（推荐 20 / 22）。其余依赖由 npm 安装。

### 4.2 常用命令

```bash
npm install          # 安装依赖
npm run build        # 构建（esbuild，约 1 秒）
npm start            # 构建并启动应用
npm run typecheck    # 类型检查
npm test             # 单元测试 + 端到端测试
npm run dist:win     # 打包 Windows（安装向导 + 便携版）
npm run dist:linux   # 打包 Linux（AppImage + deb + tar.gz）
npm run dist:all     # 同时打包 Windows 与 Linux
npm run icon         # 重新生成应用图标
```

### 4.3 在 Linux 上打包 Windows 安装包

NSIS 打包流程需要运行一次安装程序以生成卸载程序，这一步依赖 **wine**：

```bash
sudo apt install wine64      # Debian / Ubuntu
sudo dnf install wine        # Fedora
```

若构建机无法安装 wine，可只执行 `npm run pack:dir` 得到 `release/win-unpacked/`，
打包为 ZIP 即为免安装便携版，功能与安装版完全一致。

## 五、已知限制

| 项 | 说明 |
| --- | --- |
| macOS 安装包 | 配置已就绪，但需在 macOS 机器上执行构建（Electron 限制） |
| 代码签名 | Windows 与 macOS 产物均未做代码签名，首次运行可能出现系统安全提示 |
| Word / LaTeX / ePub / RTF 导出 | 依赖用户自行安装 Pandoc；未安装时导出对话框会给出明确提示，HTML 与 PDF 导出不受影响 |
| 云同步 / 协作 / 插件系统 | 属需求中的 P2 远期项，本次仅预留数据库表与接口位置，未实现 |
| 拼写检查 | 已接入设置开关与浏览器拼写检查能力，未做中文词库增强 |
| 全局搜索的中文分词 | FTS5 的 unicode61 分词对中文连写支持有限，已通过"原文 LIKE"通道补齐，功能正常 |
| 查找条位置 | 固定在编辑区右上角（与 VS Code 一致），按 `Esc` 或点击 ✕ 关闭 |
| 超长文档性能 | 块级元素扫描结果按文档对象缓存，纯光标移动不重算；10 万字文档实测流畅，但极端场景（数十万字）仍有优化空间 |
