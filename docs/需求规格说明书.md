## 一、项目概述

### 1.1 项目背景

Typora 以"所见即所得（WYSIWYG）"的实时渲染编辑体验重新定义了 Markdown 写作工具：用户在编辑时看到的排版即为最终效果，无需分屏预览。但其**收费、闭源**，且不支持插件扩展。

本项目的目标是开发一款**功能对标 Typora、开源免费、轻量高性能**的 Markdown 编辑器，命名为「花生苗 Markdown 编辑器」，让中文用户拥有一款可自由使用、可二次开发的专业写作工具。

### 1.2 项目目标

| 编号 | 目标 | 说明 |
| --- | --- | --- |
| G-01 | 跨平台 | Windows 10/11、macOS 11+、主流 Linux 发行版 |
| G-02 | 即时渲染 | 实现 Live Preview：光标所在行显示源码，其余行直接显示排版结果 |
| G-03 | 简洁优雅 | 极简 UI、无干扰写作、主题可定制 |
| G-04 | 语法完备 | 支持 CommonMark/GFM 全量语法 + 公式、图表、脚注等扩展 |
| G-05 | 高效输入 | 完整快捷键体系，支持自定义、冲突检测、导入导出 |
| G-06 | 零配置分发 | **用户下载安装包后双击即装即用，无需安装 Node、Python、编译器或任何运行时环境** |
| G-07 | 独立界面 | **软件拥有自绘的原生窗口界面，运行时不依赖浏览器、不打开任何网页标签页** |
| G-08 | 开源免费 | MIT 协议开源，代码全中文注释，欢迎社区共建 |

### 1.3 目标用户

| 用户群 | 典型场景 | 核心诉求 |
| --- | --- | --- |
| 程序员 / 技术写作者 | 技术文档、API 说明、README | 代码高亮、表格、导出 HTML |
| 学生 / 科研人员 | 笔记、论文草稿 | LaTeX 公式、大纲、PDF 导出 |
| 博客作者 / 自媒体 | 公众号、博客文章 | 图片自动保存、字数统计、导出长图 |
| 文档工程师 | 产品手册、知识库 | 文件树工作区、全局搜索、版本历史 |

### 1.4 产品定位

> **开源免费 + 实时渲染 + 轻量高性能 + 插件生态**

### 3.2 Markdown 语法支持

#### 3.2.1 基础语法（P0）

- 标题 H1–H6（`#` ~ `######`），支持 Setext 形式
- 粗体 `**`、斜体 `*`、粗斜体 `***`、删除线 `~~`
- 行内代码 `` `code` ``
- 有序列表、无序列表（支持 `-` `*` `+` 三种符号）
- 任务列表 `- [ ]` / `- [x]`，复选框可点击
- 引用块 `>`（支持嵌套）
- 代码块（围栏式 + 缩进式），**带语法高亮**
- 水平分割线 `---`
- 链接 `[文本](url)`、自动链接、引用式链接
- 图片 `![alt](src)`，支持拖拽与粘贴
- 表格（GFM 风格），支持对齐方式
- 转义字符 `\*`

#### 3.2.2 扩展语法（P1）

| 语法 | 标记 | 渲染方案 |
| --- | --- | --- |
| 行内数学公式 | `$E=mc^2$` | KaTeX |
| 块级数学公式 | `$$ ... $$` | KaTeX，居中，可编号 |
| 流程图 | ` ```mermaid ` | Mermaid |
| 时序图 / 甘特图 / 类图 | ` ```mermaid ` | Mermaid |
| 脚注 | `[^1]` | 文末脚注区 |
| 目录 | `[TOC]` | 根据标题自动生成 |
| 上标 / 下标 | `x^2^` / `H~2~O` | HTML 标签 |
| 高亮 | `==text==` | 黄色背景 |
| Emoji 短代码 | `:smile:` | 映射为 😄 |
| YAML Front Matter | `---` 包裹 | 折叠展示，可解析元数据 |
| 定义列表 | `术语` + `: 定义` | `<dl>` |

#### 3.2.3 高级特性（P2）

- 数据图表（折线 / 柱状 / 饼图），基于 ECharts
- 化学公式（mhchem 扩展）
- 自定义容器：`::: warning` / `::: tip` / `::: danger` 提示框

## 五、非功能性需求

### 5.1 性能

| 编号 | 指标 | 目标值 |
| --- | --- | --- |
| N-01 | 打开 1 MB 文档耗时 | < 500 ms |
| N-02 | 按键到上屏延迟 | < 16 ms（60 fps） |
| N-03 | 长文档支持 | 10 万字以上流畅编辑 |
| N-04 | 冷启动时间 | < 2 s |
| N-05 | 内存占用（普通文档） | < 300 MB |
| N-06 | 安装包体积 | < 120 MB |

### 5.2 兼容性

- Windows 10 / 11（x64）
- macOS 11+（Intel 与 Apple Silicon）
- Ubuntu / Debian / Fedora / Arch 等主流发行版（x64）
- HiDPI 高分屏与系统缩放适配
- 文件编码：UTF-8（含 BOM）、GBK 读取兼容
- 换行符：LF / CRLF 自动识别与保持

### 5.3 可用性

- 界面简洁，新手无需学习即可上手
- 内置帮助菜单与快捷键查询表
- 崩溃恢复：异常退出后下次启动恢复未保存内容
- 错误日志落盘，便于问题反馈

### 5.4 安全性

- 本地优先，**默认不上传任何用户数据**
- 渲染 HTML 时禁用脚本执行（沙箱化），防止恶意 Markdown 注入
- 外部链接默认使用系统默认浏览器打开，不在应用内加载远程页面
- Node 集成在渲染进程中关闭（`contextIsolation: true`、`nodeIntegration: false`）

### 5.5 可扩展性

- 插件 API 与主题 CSS 规范
- 支持自定义命令与脚本（P2）

## 七、技术架构

### 7.1 技术选型

| 层次 | 选型 | 理由 |
| --- | --- | --- |
| 桌面框架 | **Electron 3x** | 免配置分发（内置 Chromium + Node）、跨平台成熟、自带 PDF 导出能力 |
| 语言 | **TypeScript** | 类型安全，全中文注释 |
| 构建 | **esbuild** | 极速，单依赖，无需复杂配置 |
| 编辑器内核 | **CodeMirror 6** | 轻量（约 200 KB）、装饰器 API 可精确实现"源码/渲染混合"效果 |
| Markdown 解析 | **markdown-it** | 插件生态成熟（脚注、任务列表、上下标等） |
| 数学公式 | **KaTeX** | 渲染速度快，体积小 |
| 代码高亮 | **Shiki** | 使用与 VS Code 相同的 TextMate 语法，分词粒度细（关键字/变量/运算符/标点各有独立配色）；按需加载，不拖慢启动 |
| 图表 | **Mermaid** | 流程图 / 时序图 / 甘特图一站式 |
| 本地存储 | **node:sqlite**（Node 内置） | 免原生模块编译，打包零风险；支持 FTS5 全文检索 |
| PDF 导出 | Electron `printToPDF` | 无需 Puppeteer/wkhtmltopdf，零外部依赖 |
| 图片长图导出 | Electron 页面截图 API | 零外部依赖 |
| 打包 | **electron-builder** | NSIS 自定义安装路径与快捷方式配置完备 |
| 测试 | Node 内置 `node:test` + Electron 端到端脚本 | 免额外测试框架依赖 |

> **选型说明**：需求原文档建议 Tauri。本项目改为 Electron，原因是硬性需求 N-10"用户免配置环境 + 独立 UI + 开箱即用"通过 Electron 可直接满足，且 PDF 导出（`printToPDF`）与长图导出为内置能力，无需 Puppeteer 与额外 200 MB 依赖；同时 Tauri 在 Linux 下依赖系统 WebKitGTK 版本，与"免配置"要求冲突。

### 7.2 架构分层

```text
┌───────────────────────────────────────────────┐
│  UI 层（自绘标题栏 / 侧边栏 / 标签页 / 状态栏）  │
├───────────────────────────────────────────────┤
│  编辑器内核（CodeMirror 6 + 实时渲染装饰器）    │
├───────────────────────────────────────────────┤
│  渲染引擎（markdown-it + KaTeX + Mermaid）      │
├───────────────────────────────────────────────┤
│  业务逻辑层（文件 / 导出 / 设置 / 快捷键）      │
├───────────────────────────────────────────────┤
│  系统层（Electron 主进程 + IPC + node:sqlite）  │
└───────────────────────────────────────────────┘
```

### 7.3 进程模型与安全

| 进程 | 职责 |
| --- | --- |
| 主进程 | 窗口生命周期、原生菜单、文件读写、导出、SQLite、设置持久化 |
| 预加载脚本 | 通过 `contextBridge` 暴露最小化、类型化的 IPC 接口 |
| 渲染进程 | 全部 UI 与编辑器逻辑；`nodeIntegration: false`、`contextIsolation: true` |

### 7.4 关键技术难点与对策

| 难点 | 对策 |
| --- | --- |
| 即时渲染的光标定位与选区映射 | 使用 CodeMirror 6 `Decoration.replace` 隐藏语法标记，语法标记仅在光标所在行展开；通过 `ViewPlugin` 按视口增量计算，保证映射稳定 |
| 大文档性能 | CodeMirror 6 原生视口渲染 + 装饰器仅计算可见范围 + 防抖重算 |
| 图片路径管理 | 统一 `path.relative` 规范化，跨平台分隔符转换 |
| PDF 导出保真 | 使用独立隐藏窗口加载渲染后的 HTML + 专用 `@media print` 样式与分页控制 |
| 表格内编辑体验 | 自绘浮动工具条 + 表格行列增删操作，直接改写源码文本 |

采用 SQLite（`node:sqlite`），数据库文件位于用户数据目录 `huashengmiao.db`。

### 8.1 表清单

| 表名 | 用途 |
| --- | --- |
| `documents` | 文档索引与元数据 |
| `document_versions` | 文档版本快照 |
| `tags` / `document_tags` | 标签体系 |
| `images` | 图片资源登记 |
| `settings` | 键值配置 |
| `shortcuts` | 快捷键绑定 |
| `recent_files` | 最近打开文件 |
| `search_index` | FTS5 全文索引 |
| `export_history` | 导出历史 |
| `sync_log` | 同步日志（预留） |
| `plugins` | 插件登记（预留） |

### 8.2 核心 DDL

```sql
-- 文档表
CREATE TABLE IF NOT EXISTS documents (
    id             INTEGER PRIMARY KEY AUTOINCREMENT,
    title          VARCHAR(256) NOT NULL DEFAULT '未命名',
    file_path      VARCHAR(512) UNIQUE,
    content_hash   VARCHAR(64),
    word_count     INTEGER DEFAULT 0,
    char_count     INTEGER DEFAULT 0,
    line_count     INTEGER DEFAULT 0,
    is_favorite    BOOLEAN DEFAULT 0,
    is_deleted     BOOLEAN DEFAULT 0,
    created_at     DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at     DATETIME DEFAULT CURRENT_TIMESTAMP,
    last_opened_at DATETIME
);

-- 版本快照表
CREATE TABLE IF NOT EXISTS document_versions (
    id           INTEGER PRIMARY KEY AUTOINCREMENT,
    document_id  INTEGER NOT NULL,
    content      TEXT    NOT NULL,
    content_hash VARCHAR(64),
    version_no   INTEGER NOT NULL,
    size_bytes   INTEGER,
    created_at   DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (document_id) REFERENCES documents(id) ON DELETE CASCADE
);

-- 配置表
CREATE TABLE IF NOT EXISTS settings (
    key        VARCHAR(128) PRIMARY KEY,
    value      TEXT,
    value_type VARCHAR(16) DEFAULT 'string',
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- 快捷键表
CREATE TABLE IF NOT EXISTS shortcuts (
    id           INTEGER PRIMARY KEY AUTOINCREMENT,
    command_id   VARCHAR(128) NOT NULL UNIQUE,
    command_name VARCHAR(128) NOT NULL,
    keybinding   VARCHAR(128),
    is_default   BOOLEAN DEFAULT 1,
    scope        VARCHAR(32) DEFAULT 'global',
    updated_at   DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- 全文索引
CREATE VIRTUAL TABLE IF NOT EXISTS search_index USING fts5(
    document_id UNINDEXED, title, content, tokenize = 'unicode61'
);
```

> 完整 DDL 见《详细设计说明书》第 4 章。
